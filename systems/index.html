Systems

One page per game system: what the engine does in that area, which functions have been mapped, and what is still open.

At a glance

What a page holds
A summary, key functions, structs and globals, patch points and open questions, always in that order.
Generated parts
The function tables come from symbols/functions.csv in Paleblood; everything else is written by hand.
Where to start
Frame timing: the per-frame loop that the other systems hang from.

How to read a system page

Every page follows the same five sections, so you can compare systems side by side:

  1. Summary: how the system works, in prose, with call chains and worked examples.
  2. Key functions: the generated table of mapped functions, with address, size and status.
  3. Structs and globals: the data layouts and singletons the functions use.
  4. Patch points: where community patches or Paleblood's own options change the system.
  5. Open questions: what is not yet known.

Provenance (pull requests, sources, corrections) sits in collapsed boxes, so the explanation reads straight through.

The pages

Page What it covers
Frame timing The frame limiter, the frame step, delta time and the task manager's frame
Kernel The engine's thread, mutex and condition-variable wrappers over the PS4 kernel
Event Event entries, Lua event scripts and event flags
Camera Camera update, targeting, world collision and field of view
Input The pad manager and its per-frame step
Character Per-frame updates of character instances
AI The shared Havok AI world and its per-frame step
Physics The rigid-body world, its tables, and the physics-instance constructor
Render The render frame update and swap-chain presentation
Loading File, Fios and PlayGo interfaces the executable imports
Audio Sound playback, mixing and music

Adding a system
  1. Add a directory under game/ in Paleblood.
  2. Add a page here (copy any existing one).
  3. Add the page to the site navigation.
  4. Run tools/sync_progress.py.
