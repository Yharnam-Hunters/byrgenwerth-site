Engine

The engine's shared plumbing that every system leans on: its fatal error report, its check for missing singletons, its reference-counted objects, and small helpers such as writing a line to the standard error stream.

At a glance

Scope
Engine-wide helpers in Paleblood's game/engine/: the fatal error report and singleton check, reference counting, and replaced engine utility functions.
Verified
engine_write_stderr, the string helpers, wide-string set-up, owner storage and a handle-table lookup are edge-verified against constructed cases.
Open
Who calls the stderr writer during play, and with what text.

Summary

What every system shares

Most replaced functions lean on a few engine-wide pieces:

  • The fatal error report (0x024b55b0) takes a source file, a line and a message. In the shipped game it logs and returns, so the code after it keeps running; Ghidra wrongly treats it as never returning (see Ghidra & PS4 Quirks).
  • The singleton check. Many systems are singletons (FrpgNetMan, SprjEventFlagMan, ...). Code that needs one reports it by name through the fatal error report when it is missing, then reads it again and uses whatever is there.
  • Reference-counted objects (DLReferenceCountObject). An object counts its holders; dropping the last reference destroys it through its first virtual function, and dropping one more than it has is reported as an invalid unref. The render frame update and the Chalice Dungeon gate's handle share this code (#185).

Writing to standard error

engine_write_stderr (0x0111a740) writes a text to the standard error stream: it reads the C library's stderr once, passes the text to fputs, ignores the result, and returns 0.

How the stderr writer was verified

By @evill33t in #113, brought up to date with main and merged in #205. Its 28 constructed edge cases pass against the original on current main, and an independent review approved it; no frame-rate patch edits it. It has not been checked on frames recorded from a real game run.

Comparing strings

Two byte-string comparisons compare signed bytes and return the difference at the first mismatch: engine_compare_signed_strings (0x011c4970) runs to the end of the strings, and engine_compare_signed_prefix (0x011c4990) stops after a length, still comparing the first byte when the length is zero or negative. All their callers are in FMOD's code (see Audio).

More string helpers

Since 4 November the engine's small C-string helpers are mapped too, by @evill33t: engine_string_length (0x011c47f0, a strlen whose result is cut to 32 bits, #288), engine_ascii_to_upper_in_place and engine_ascii_to_lower_in_place (0x011c4910, 0x011c4940: change letters in place and return the string, #281), and engine_compare_ascii_ignoring_case (0x011c49c0, compares two strings ignoring letter case, #282).

Wide strings and owned storage

  • engine_wide_string_destroy (0x02a44140) releases a wide (16-bit character) string, and engine_initialize_static_wide_string_0217ffb0 sets up one static wide string the first time it is needed, guarded so it happens once (#284).
  • engine_release_owner_storage and engine_resize_owner_storage (0x0132c590, 0x0132c6c0) free an object's storage block through its allocator, or replace it with a new 16-byte-aligned block of the requested size (#285). What kind of object owns the block is not known yet; its only known caller is 0x02713870.

Looking up a table entry by handle

engine_entry_manager_resolve (0x01314320) turns a handle into an entry: it checks that the table is enabled, rejects the all-ones handle, uses the handle's low 32 bits as an index checked against the table's capacity, and rejects an empty entry. Its callers are a family of functions at 0x02717f30-0x02718c80 and 0x0210f5a0; what the table holds is not known yet.

How these were verified

By @evill33t: the comparisons in #107, merged in #274 (18 and 24 cases), and the lookup in #110, merged in #276 (25 cases). Each was brought up to date with main, its constructed edge cases pass against the original on current main, and an independent review approved it.
