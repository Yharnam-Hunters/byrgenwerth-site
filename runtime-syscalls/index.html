Runtime system-call notes

This page records the public API contracts and the evidence currently available for calls in runtime issue #34, with a separate network byte-order slice from issue #41. A platform manual describes that platform; it does not prove every detail of the PS4 implementation. The notes below separate documented behavior from what remains unknown for the target.

What the game evidence shows

The executable imports getpagesize and gettimeofday from libScePosix. The game's bundled libc.elf imports clock_gettime, getpagesize, getpid, and gettimeofday from libkernel. These import rows establish required names, not every call argument or the behavior of the PS4 implementation.

The frame limiter calls gettimeofday with a null timezone argument. A separate verified game helper calls sceKernelClockGettime with clock ID 4, identified as CLOCK_MONOTONIC. This confirms that ID for the SCE entry point. It does not establish which IDs the game passes to the imported clock_gettime wrapper, or whether 4 is accepted there.

Interfaces and behavior

Call Arguments and representation Publicly documented result and errors Still unknown for the PS4 target
getpagesize(void) No arguments; returns the system page size in bytes. The number is platform-specific. Linux and FreeBSD document the byte count. getpagesize is not in current POSIX; portable code uses sysconf(_SC_PAGESIZE). The manuals do not define a general error return. The target's page-size value and behavior under unusual configurations. Never substitute the build host's page size without evidence.
getpid(void) No arguments; returns a pid_t for the calling process. POSIX specifies success and no error return. Linux PID namespaces scope process IDs; process-ID scope and lifetime are platform-specific. The guest-visible ID and its scope. The host PID is not automatically the correct guest result.
clock_gettime(clock_id, tp) clock_id selects a clock. tp points to a struct timespec; POSIX represents it as seconds (tv_sec) and nanoseconds (tv_nsec), normalized so tv_nsec is from 0 through 999,999,999. POSIX returns 0 on success and -1 with errno on failure; an unsupported clock ID is EINVAL. Linux and BSD manuals document pointer errors, but exact error mapping is platform-specific. The target structure layout, IDs accepted by the imported wrapper, and its pointer/error behavior. ID 4 is confirmed only for sceKernelClockGettime.
gettimeofday(tv, tz) tv points to a struct timeval: seconds since the Epoch and microseconds (tv_usec from 0 through 999,999). The game passes null for tz. This is wall time and may jump; it is not a monotonic elapsed-time clock. Older POSIX specified 0 on success but left errors undefined. Linux reports -1/EFAULT for inaccessible pointers and ignores tz. POSIX.1-2024 removed the interface. The target structure layout, bad-pointer behavior, non-null timezone behavior, and error mapping. The known game call passes null for tz.

The numeric clock IDs in POSIX are implementation-defined. Linux also has IDs such as CLOCK_MONOTONIC_RAW and CLOCK_BOOTTIME; FreeBSD has its own clock set, including CLOCK_UPTIME variants. Those names and numbers are not evidence for PS4 behavior. No inspected source confirms that the game's imported clock_gettime receives CLOCK_REALTIME, CLOCK_MONOTONIC_RAW, CLOCK_BOOTTIME, or any ID besides the separate SCE call's value 4.

Network byte-order conversions

Paleblood imports four integer conversion calls from libSceNet in eboot: sceNetHtonl, sceNetHtons, sceNetNtohl, and sceNetNtohs. Their public SCE declarations use unsigned 32-bit and 16-bit integer arguments and results. The documented byte-order contract converts between host order and big-endian network order; the reverse direction uses the same operation. For the project's AMD64 guest ABI, this is byte reversal. The four calls are pure value conversions and do not require socket or online state.

The declaration reference below is PSP2SDK's public net.h API surface; it supplies the SCE function names and integer widths, not a PS4 runtime trace. The FreeBSD manual documents the standard host/network conversion contract. This evidence supports only these four conversions. It does not establish behavior for libSceNet sockets, name resolution, epoll, or offline-state queries. Those imports remain unimplemented until their own evidence is available.

Implementation and tests

Implement only behavior supported by public documentation, independent reverse engineering, or observed behavior. Keep unresolved target behavior visible; do not fabricate a return value to make tools/boot.py advance. Add cases to the RT_SYSLIB unit test for each established behavior and error path. Runtime-only contributions do not need a game dump, captures, or function-level verify.py results; CI builds and runs the runtime and syslib tests.
