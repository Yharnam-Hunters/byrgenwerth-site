Runtime call reference

The runtime's own detailed notes on each system call: the evidence, the exact behavior and what stops by name. This page is copied from Paleblood's docs/runtime-syscalls.md every time the wiki syncs, so it always matches the code.

For the reader-friendly explanation of the same calls, start with Runtime system calls.

This page records contracts used to implement small runtime calls in issues #34 and #41. Public standards and manuals describe portable or platform-specific API behavior; they do not by themselves prove every detail of the PS4 implementation. Keep the distinction below, and leave unresolved behavior unresolved until public documentation, our own reverse engineering, or observed behavior settles it.

Evidence in this repository

The runtime registry distinguishes behavior it implements from diagnostics for behavior that is still unknown. RT_SYSLIB entries are callable implementations and count toward coverage; RT_SYSLIB_UNRESOLVED entries remain callable so a reached import can fail with a useful name, but do not count as implemented or as supplied imports in progress reports.

symbols/imports.csv records getpagesize and gettimeofday as imports of eboot from libScePosix; libc.elf imports clock_gettime, getpagesize, getpid, and gettimeofday from libkernel. Import rows establish that the names are required, not their arguments, return values at every call site, or all clock IDs.

The eight hash-verified target images (eboot.elf and the seven modules, tools/check_target.py) all state p_align 0x4000 for every PT_LOAD segment, with p_offset congruent to p_vaddr modulo 0x4000 (the difference is exactly 0x4000 in each; readelf -l prints the headers).

The decompiled frame limiter calls gettimeofday with a null timezone argument. A separate verified clock helper calls sceKernelClockGettime with clock ID 4, named CLOCK_MONOTONIC in that code. This confirms one monotonic clock request in the game; it does not establish every ID passed through the imported clock_gettime wrapper, or that no other ID is used in unexamined code.

Interfaces and known behavior

Function Arguments and representation Publicly documented result and errors Evidence and open questions for PS4
getpagesize(void) No arguments. Returns the target's page size in bytes. The numeric value is platform-specific. getpagesize is not in current POSIX; portable code is directed to sysconf(_SC_PAGESIZE). Linux and FreeBSD document the byte count; their manuals do not define a general error return for this function. Linux exposes it as a libc interface, not necessarily a dedicated kernel syscall. FreeBSD notes the system page size may differ from the underlying hardware page size. The import is present twice (eboot from libScePosix, libc.elf from libkernel), so both library names are registered against one implementation. The target images bound the value but do not pick one: every PT_LOAD of the eight hash-verified ELFs has p_align 0x4000 with p_offset congruent to p_vaddr modulo 0x4000, and the ELF ABI's congruence rule then limits the system page size to a divisor of 16384 (4096, 8192 or 16384); p_align is the alignment the image requires, not the page size the system reports. Stock FreeBSD on AMD64 uses 4096, and Sony's open-source page confirms the FreeBSD kernel is used but publishes the upstream sources, not the console's modifications, so no public source names the PS4's own value. The runtime entry is therefore registered with RT_SYSLIB_UNRESOLVED, so a boot that reaches it names the call, and it does not count as implemented (runtime/syslib/kernel.c). What would settle it: one observed getpagesize() or sysconf(_SC_PAGESIZE) result on a console, or a guest call site whose page arithmetic shows the granularity the system uses. See the section "getpagesize: observed, inferred, unknown" below; do not hard-code the build host's page size.
getpid(void) No arguments. Returns a pid_t naming the calling process. POSIX specifies that it succeeds and has no error return. Linux process IDs are scoped by PID namespaces; other systems have their own process-ID scope and lifecycle rules. The import is present, but this repository does not establish the guest-visible process ID or its scope. Returning the host PID is not justified by the API contract alone.
clock_gettime(clock_id, tp) clock_id selects a clock; tp points to a struct timespec. On the POSIX interface, tv_sec is seconds and tv_nsec is nanoseconds in [0, 1,000,000,000). The exact target structure layout still needs ABI evidence. POSIX uses 0 for success and -1 with errno for failure. An unsupported clock ID is an EINVAL case. Linux and BSD manuals document additional pointer-error details; use the target contract rather than assuming the host's errno mapping. The imported wrapper is present. The verified sceKernelClockGettime call requests ID 4 (CLOCK_MONOTONIC). That is evidence for the SCE entry point only, not proof of the libc wrapper's IDs. Other IDs and exact PS4 error and pointer handling remain unresolved. Unknown IDs must not silently return a fabricated time.
gettimeofday(tv, tz) tv points to a struct timeval: seconds since the Epoch and microseconds in [0, 1,000,000). The historical timezone argument is passed as null at the confirmed game call site. The exact target structure layout still needs ABI evidence. The wall clock can jump and is not a monotonic elapsed-time source. Historical POSIX specified a zero return on success and left errors undefined; Linux documents -1/EFAULT for inaccessible pointers and ignores the timezone argument. POSIX.1-2024 removed the interface. The imported wrapper and game call sites are present; the game passes null for the second argument. Exact target behavior for bad pointers, non-null timezone arguments, and error mapping is not established. Do not silently ignore an error without evidence.
sched_yield(void) No arguments. Returns int. POSIX: the calling thread gives up the processor until it is again at the head of its thread list; 0 on success, -1 with errno otherwise, and POSIX defines no error case for it. FreeBSD documents the same call. Imported by libc.elf from libkernel. Implemented: a guest thread runs on a host thread, so the runtime yields the host thread and returns 0 (runtime/syslib/kernel_thread.c). A host failure has no FreeBSD error number to report, so it stops by name. Not observable in a unit test: that the host scheduler actually ran another thread.
scePthreadYield Asks for the same yield through the thread library. The PS4-visible signature is not established. FreeBSD's pthread_yield(3) is void; Linux's is int (always 0). No PS4-specific public source gives the SCE name's declaration. Imported by eboot and libc.elf from libkernel; no call site in this repository shows whether the caller reads a result. Registered with RT_SYSLIB_UNRESOLVED: the entry stops by name and does not count as implemented. What would settle it: a guest call site showing whether the return register is read after the call, or a PS4-specific public declaration. Do not assume an int or 0 from the FreeBSD or Linux analogues.
memcpy(dest, src, n), memset(dest, c, n) (libSceLibcInternal) void *memcpy(void *, const void *, size_t) and void *memset(void *, int, size_t), the ISO C declarations. ISO C 7.24.2.1 and 7.24.6.1: memcpy copies n bytes from src to dest; memset writes c converted to unsigned char into the first n bytes; both return dest. Overlapping memcpy regions and null pointers are undefined behaviour. Imported by libSceFios2.elf from libSceLibcInternal (symbols/imports.csv). Implemented with the host's own functions, since the standard fixes the whole result and no target-specific value is involved (runtime/syslib/kernel.c). Not modelled: what the PS4 C library does for the undefined cases; no public source or call site establishes it.
sceKernelUsleep(microseconds) (libkernel), usleep(microseconds) (libScePosix) One unsigned 32-bit count of microseconds, returning int. For sceKernelUsleep the guest fixes the shape: the verified call sites in game/frame_timing/frame_limiter.cpp and game/render/swap_chain_present.cpp declare it as int(uint32_t microseconds), and their cases expect 0. FreeBSD's useconds_t is 32-bit unsigned. FreeBSD usleep(3): suspends the thread for the given microseconds, 0 on success, -1 with EINTR if a signal interrupts it. SUSv2 also let usleep fail with EINVAL from 1,000,000 on; FreeBSD and POSIX.1-2008 (which removed usleep) have no such limit. sceKernelUsleep is imported by eboot and libSceFios2.elf, usleep by eboot. Implemented: the host thread sleeps at least the requested time and the call returns 0; a host signal is not a guest event, so the sleep resumes with the time left (runtime/syslib/kernel.c). Open: usleep with 1,000,000 or more, which stops by name because no PS4-specific source says whether the guest sleeps or gets EINVAL; and the SCE error, if any, for sceKernelUsleep, which the guest's sites never check.
scePthreadRwlockInit(rwlock, attr, name), scePthreadRwlockDestroy(rwlock), scePthreadRwlockRdlock(rwlock), scePthreadRwlockWrlock(rwlock), scePthreadRwlockTryrdlock(rwlock), scePthreadRwlockTrywrlock(rwlock), scePthreadRwlockUnlock(rwlock) (libkernel) A pointer to the guest's rwlock variable (Init also an attribute pointer and a name, as scePthreadMutexInit); each returns int32_t. No call site in this repository shows these shapes; they come from the public OpenOrbis libkernel.h declarations, supporting evidence for the shapes only, and match FreeBSD's pthread_rwlock_*. POSIX pthread_rwlock_*, as FreeBSD libthr (thr_rwlock.c) and the kernel's umtx read-write lock (kern_umtx.c) implement it: a static initializer (NULL) set up on first use and a destroyed rwlock holding 1 (thr_private.h); EINVAL for a destroyed rwlock; EBUSY from the try forms when the lock is not available; destroying does not check whether the lock is held, and leaves an unused initializer in place; unlocking is EPERM when another thread holds the write lock or when nobody holds the lock, and readers are counted, not named; a thread that locks again while holding the write lock is not given an error, it waits forever (no owner check in do_rw_wrlock or do_rw_rdlock). The SCE name returns 0x80020000 plus the error number. Imported by eboot and libSceFios2.elf (Tryrdlock by libSceFios2.elf only; symbols/imports.csv). Implemented on a host rwlock that also records the writer and the reader count, which the host does not expose, for the unlock answers (runtime/syslib/kernel_rwlock.c). A missing variable answers EINVAL, as the mutex calls do; unlocking a never-used initializer is EPERM, as for the mutex. Stops by name: Rdlock or Wrlock while the caller holds the write lock (the system would wait forever, the host answers EDEADLK; neither is useful to return), and an attribute object passed to Init (no imported call creates one, so its contents are not established; an empty attribute variable means the defaults, as in libthr). Not part of this entry: scePthreadRwlockTimedrdlock and Timedwrlock (imported by eboot; only OpenOrbis gives their microsecond timeout, no call site does) and the libScePosix names.
__stack_chk_fail(void) (libkernel) No arguments, no result: void __stack_chk_fail(void), and it never returns (LSB; FreeBSD libc declares it __dead2). Compiler-generated code calls it, not application code. LSB Core: the function that called it is aborted with a message that a stack overflow was detected, and the program then exits. FreeBSD libc logs "stack overflow detected; terminated" and ends the process with SIGABRT. Imported by eboot, libSceFios2.elf and libc.elf from libkernel (symbols/imports.csv). Implemented as a stop by name (rt_fatal, which aborts): ending the program is the whole guest-visible contract, so the entry counts as implemented (runtime/syslib/kernel.c). Not covered: the PS4's own message or crash report, which the guest cannot observe after it ends; and __stack_chk_guard, a separate data import whose PS4 value is not established (an unbound data import gets a zeroed page, runtime/boot.c).
scePthreadCondInit(cond, attr, name), scePthreadCondDestroy(cond), scePthreadCondSignal(cond), scePthreadCondBroadcast(cond), scePthreadCondWait(cond, mutex), scePthreadCondTimedwait(cond, mutex, microseconds) (libkernel) Pointers to the guest's cond and mutex variables; each returns int32_t. The guest fixes the wait shapes: the verified game/kernel/condition_wait.cpp declares Wait as int32_t(void *cond, void *mutex) and Timedwait as int32_t(void *cond, void *mutex, uint32_t timeout_us), a relative timeout in microseconds, not POSIX's absolute timespec. The public OpenOrbis libkernel.h declares all six with these shapes (Init with an attribute pointer and a name, as scePthreadMutexInit); it is supporting evidence for the shapes only. POSIX pthread_cond_*, as FreeBSD libthr implements it (thr_cond.c): a static initializer (NULL) set up on first use; a destroyed cond holds 1 (thr_private.h); EINVAL for a destroyed cond; EBUSY to destroy one with waiters; destroying an unused initializer succeeds and leaves it in place; EPERM when the waiter does not own the mutex, for every mutex type, EINVAL when the mutex is destroyed (_mutex_owned, thr_mutex.c); ETIMEDOUT when a timed wait expires; a recursive mutex is released completely for the wait and its count restored after (_mutex_cv_unlock, _mutex_cv_lock). The SCE name returns 0x80020000 plus the error number. scePthreadCondWait and Timedwait are imported by eboot, libSceFios2.elf and libc.elf, the other four by libSceFios2.elf and libc.elf (symbols/imports.csv). The guest's call site checks exactly 0x80020001 (EPERM), 0x80020016 (EINVAL) and 0x8002003c (ETIMEDOUT). Implemented on a host cond on the monotonic clock (runtime/syslib/kernel_mutex.c): the timed wait times out once the given microseconds have passed since the call (0: at once). A missing cond or mutex variable answers EINVAL, as the mutex calls do. Stops by name: an attribute object passed to Init (no imported call creates one, so its contents are not established; an empty attribute variable means the defaults, as in libthr). A wait with a recursive mutex releases every level the caller holds and takes them back after, as libthr does: the runtime tracks each recursive mutex's owner and depth, and releases the extra levels itself around the host wait. Not reproduced: the ownership check for normal and adaptive mutexes, which the host does not make; the error-checking default and the recursive type are checked. The libScePosix names pthread_cond_init, _destroy, _signal, _broadcast and _wait (imported by eboot) are the same calls with errno values: the executable's call at 0x0247e6d7 passes (&cond, NULL) and its caller compares the result with bare error numbers (12, 16, 34, 35). pthread_cond_timedwait is not part of this entry: it takes an absolute timespec whose PS4 layout and clock are not established, so it stays unbound and stops by name.

Module loading at run time (libSceSysmodule)

Observed in our target: the executable imports sceSysmoduleLoadModule, sceSysmoduleIsLoaded and sceSysmoduleUnloadModule from libSceSysmodule; its shipped file I/O module imports the load and unload calls too. Neither imports sceKernelLoadStartModule or another loader entry (symbols/imports.csv), so a module is asked for by its system module id and nothing else. Five of the seven modules the title ships are listed with action stub in game/modules.csv, which records that the executable imports nothing from them; they are not mapped.

Documented publicly: the OpenOrbis toolchain's id list (include/orbis/_types/sysmodule.h, after psdevwiki's "Libraries" page) names the ids of those five: ORBIS_SYSMODULE_FACE 0x0038, ORBIS_SYSMODULE_SMART 0x0039, ORBIS_SYSMODULE_S3DCONVERSION 0x0086, ORBIS_SYSMODULE_HAND 0x0093 and ORBIS_SYSMODULE_HEAD_TRACKER 0x00cb. They are recorded in the sysmodule column of game/modules.csv; the runtime itself names no module (tools/check_agnostic.py): tools/boot.py passes each stub to pbboot as --stub-module ID:NAME, and the run's status (stub_modules in symbols/boot.json) says which of them the guest loaded.

Inferred: if nothing we map imports from a stub (as game/modules.csv records for the executable), answering the load without mapping the module cannot leave a call unbound; an import it would have satisfied still shows up unbound in symbols/imports.csv and stops the boot by name. Whether the executable's sites check the result beyond success, and which ids they pass, is not yet observed: the boot stops before the first load today.

System modules the runtime provides: a module the title does not ship but loads by id (it is part of the system) can be listed with action runtime once the runtime implements the functions the executable imports from it. tools/boot.py passes it like a stub, so a load is reported as done, and its imports bind to the runtime's entries by name. The first is libSceAppContent (0x00b4 in the OpenOrbis id list), below.

Unknown: the error values (a module not loaded, an id the system does not know), and whether a second load of a loaded module is counted, ignored or refused. Each is a named fatal until a console measurement or a guest call site settles it.

scePthreadAttrGetaffinity: the startup consumer and missing evidence

An affinity mask identifies the CPUs on which a thread may run. The current startup stop is a query for the main thread's mask. Returning success without the correct output would change the CPU count that the bundled C library stores; it would not implement the query.

Observed in the hash-pinned bundled libc.elf: the function at module offset 0x81a80 initializes a thread attribute, obtains the current thread, and copies its attributes. If those operations succeed, its call at libc.elf+0x81ad0 passes the address of that attribute variable in RDI and the address of a zero-initialized eight-byte stack slot in RSI. This is a two-pointer interface, not FreeBSD's three-argument interface with an explicit buffer size. The return site is libc.elf+0x81ad5, matching the genuine boot diagnostic. The caller does not check the affinity query's return value: after destroying the attribute it reads the slot, counts its set bits across 64 bits, and stores a 32-bit count. This establishes the consumer's memory requirements, not the real query's write width, the actual mask or its complete error contract.

The original consumer also ran through the existing harness on nine private constructed fixtures with scripted imports, using each compiler's loader. It produced the expected counts for zero, low-bit, high-bit and all-bit masks, and exercised both earlier failure branches. A scripted nonzero affinity return with a supplied mask still produced that mask's count, corroborating that this caller ignores the return. These are original-consumer observations under synthetic import behavior, not observations of PS4 affinity, recorded gameplay, complete instruction-trace verification or an original-versus-replacement comparison. No function status changes follow from them.

Public supporting evidence: the OpenOrbis homebrew header libkernel.h declares a signed 32-bit return and an attribute pointer plus an output pointer. Its comment explicitly leaves the mask type unfinished; the declaration is corroboration, not a measured PS4 contract. The FreeBSD 9.3 affinity manual describes retrieving a stored attribute mask, success/error returns and invalid attributes, but its API includes a size argument absent at this target call. Its errors and CPU-set layout cannot simply be assigned to the SCE interface.

Still required before implementation: independently establish the main thread's actual mask, how a fresh attribute differs from one filled by scePthreadAttrGet, the exact output write extent, success/error results, and invalid/null attribute or output handling. Host CPU availability and a guessed console core count establish none of these. No specific affinity implementation is added or registered by this investigation; the import remains unbound.

A useful target measurement would record the console/firmware and executable identities, the results of attribute initialization and copying from scePthreadSelf, the getter's return bits, the output bytes with adjacent canaries, and repeated observations without changing affinity. Check current claims in issue #34 before taking implementation work; mentions of the boot blocker are not themselves contributor claims. Generic gameplay capture remains separate contributor-owned work, not a reason to synthesize the missing affinity observation.

Clock IDs and platform differences

The only clock ID confirmed by a decompiled game call in this repository is 4, used with sceKernelClockGettime and identified there as CLOCK_MONOTONIC. This does not prove that the game passes 4 to the imported clock_gettime wrapper. POSIX defines clock identifiers symbolically; their numeric values are implementation-specific. Linux adds clocks such as CLOCK_MONOTONIC_RAW and CLOCK_BOOTTIME; FreeBSD has its own clock set, including CLOCK_UPTIME variants. Their names and numeric values are not interchangeable evidence for PS4 behavior.

CLOCK_MONOTONIC represents elapsed time from an unspecified starting point and is not the wall clock. The precise effects of suspend, rate correction, and resolution vary by implementation. gettimeofday and CLOCK_REALTIME represent wall time tied to the Epoch and can move when system time changes. No source examined here establishes that the game asks the imported clock_gettime wrapper for CLOCK_REALTIME, CLOCK_MONOTONIC_RAW, CLOCK_BOOTTIME, or another ID.

Network byte-order helpers

The four libSceNet imports sceNetHtonl, sceNetHtons, sceNetNtohl, and sceNetNtohs take and return 32-bit or 16-bit unsigned integers, respectively. Public PSP2SDK API declarations provide those widths for the SCE names. The standard byte-order contract converts host order to network (big-endian) order for hton*, and reverses that conversion for ntoh*; this is documented by the FreeBSD byte-order manual. Paleblood's guest ABI is AMD64, so these four conversions are byte reversals. Their implementations do not call host networking APIs or depend on host socket state.

This evidence supports only the four integer conversions. It says nothing about libSceNet socket, resolver, epoll, offline-state, or error behavior; those imports remain unresolved until their own contracts are established.

IPv4 text conversion (sceNetInetPton, issue #41)

The executable imports sceNetInetPton from libSceNet. Target call-site inspection found four unconditional call instructions (at 0x0085785e, 0x011c7a7b, 0x02f984f6, and 0x02df348d); each passes address family 2 and supplies the result as an IPv4 address. The consumers use a positive return as success. This establishes Bloodborne's observed call shape, not every address family supported by the PS4 library. The import thunk and pointer-table references are not additional call sites.

For the observed AF_INET path, the runtime uses the documented BSD inet_pton(3) contract: parse dotted-decimal IPv4 text into four network-order bytes, return 1 for valid input and 0 for malformed input. This conversion does not open a socket or perform network I/O. Other target address families and null-pointer error behavior remain unresolved, so the runtime emits a named diagnostic for those inputs instead of forwarding host-specific errors.

getpagesize: observed, inferred, unknown

Observed in our target (read-only; the eight images verify against target.sha256 and target.image.sha256):

  • symbols/imports.csv has exactly two getpagesize rows - eboot from libScePosix and libc.elf from libkernel. No sysconf and no quad-page call is imported, so this is the only page-size query the guest has.
  • All sixteen PT_LOAD segments of those eight images have p_align 0x4000, and in every one p_offset - p_vaddr is exactly 0x4000.
  • Three guest call sites share one shape: 0x00e04168, 0x00e04939 and 0x00e05cf9, each inside functions 0x00e04140, 0x00e045c0 and 0x00e05a80. Each is a lazy initialiser: a guard tests 0x05859ec0, the call is made, the result is cltq-extended, blsr %rax,%rcx with jne rejects it unless it is a power of two, and the value is cached in 0x05859ec8 beside three fixed siblings (0x10000, 0x40000, 0x200000).
  • 0x05859ec8 has exactly five cross-references in the executable: the three writes above and two reads, all inside those same three functions. None of them compares the cached value against a constant, and no other function reads it.

Inferred, and the premise each inference needs:

  • The ELF ABI takes p_align of a loadable segment to be a multiple of the system page size, and requires p_offset and p_vaddr to be congruent modulo the page size. If the PS4 loader follows both rules for these segments, a page size larger than 0x4000 could not map them at their fixed addresses, while any power-of-two divisor of 0x4000 could.
  • Restricting that to 0x1000, 0x2000 and 0x4000 adds a second assumption - that the page size is at least 4096 - which is ours, not observed. The guest's own blsr check is consistent with every power of two and selects none of them.
  • So p_align bounds the candidate set under our premises; it does not measure the value the kernel returns, and none of the three candidates is established.

Unknown: the number the PS4 reports. Stock FreeBSD on AMD64 uses 4096 (PAGE_SHIFT 12, sys/amd64/include/param.h), and Sony's open-source page confirms a FreeBSD kernel but publishes the upstream sources rather than the console's modifications, so that value describes the ancestor and not the target. Thread attribute detach state (scePthreadAttrSetdetachstate, issue #34)

eboot and libSceFios2.elf import scePthreadAttrSetdetachstate from libkernel, and eboot imports pthread_attr_setdetachstate from libScePosix (symbols/imports.csv). Each source below establishes a different part:

  • What the call does: POSIX pthread_attr_setdetachstate. A thread created with the attribute starts detached for PTHREAD_CREATE_DETACHED and joinable for PTHREAD_CREATE_JOINABLE.
  • Invalid detach state: POSIX and FreeBSD's pthread_attr(3) both make any other value EINVAL.
  • Invalid attribute variable: POSIX leaves a null or uninitialised attribute undefined and only recommends EINVAL, and the FreeBSD manual lists no error for it. The behaviour comes from FreeBSD libthr's _pthread_attr_setdetachstate (lib/libthr/thread/thr_attr.c), which returns EINVAL when the variable is null or holds no attribute object.
  • The numbers: FreeBSD's <pthread.h> defines the two states as 0 and 1. The OpenOrbis homebrew SDK header (include/orbis/_types/pthread.h) defines ORBIS_PTHREAD_CREATE_JOINABLE and ORBIS_PTHREAD_CREATE_DETACHED with the same values. That header follows FreeBSD's text, so it corroborates the numbers rather than measuring them independently.

As with the mutex functions (runtime/syslib/kernel_mutex.c), the SCE name returns 0x80020000 plus the error number, and the POSIX name returns the number itself.

Still open: the detach state a fresh attribute starts with, and the one scePthreadAttrGet copies from a running thread. Both are values the system supplies. POSIX makes joinable the default, but nothing we can cite confirms what the PS4 reports. In FreeBSD libthr, _pthread_create (thr_create.c) uses that same default (_pthread_attr_default) when it is given no attribute variable or an empty one. The runtime treats both cases as the unknown default, so the outcome, a fatal, does not depend on the PS4 matching libthr there.

How the runtime keeps that open:

  • The attribute records a state only when one is set (has_detach_state). scePthreadAttrGet replaces the whole attribute, as libthr's pthread_attr_get_np does, so a state set before the copy is dropped.
  • By convention, thread creation reads the state through rt_thread_attr_detach_state (runtime/include/runtime/process.h) and never from the field. A fresh attribute's field holds zero, which is the joinable value, so reading the field directly would assume joinable silently.
  • For no variable, an empty variable, or a state nobody set, the reader stops the process (rt_fatal), names the call that asked, and says which of those cases it hit.

What would settle it: an observed scePthreadAttrGetdetachstate result on a console, for a fresh attribute and for one filled by scePthreadAttrGet from the main thread. Guest call sites would also settle it: a thread created without a detach state being set, then joined or detached (scePthreadJoin, pthread_join and scePthreadDetach are imported).

  • GPU access. The executable maps with protection 3 and 0x33, CPU and GPU read/write (0x10 and 0x20 in the public SDK list). The runtime has no GPU yet, so the host mapping takes the CPU bits.
  • What stops by name. Every case whose PS4 answer is not established stops with the function's name:
  • lengths, starts or alignments that are not multiples of 16 KiB (the granularity the executable's calls use);
  • memory types other than 0, 3 and 10;
  • map flags, and an address hint without flags;
  • protection other than CPU and GPU read and write;

Signal masks (_sigprocmask, issue #34)

_sigprocmask(how, set, old) is FreeBSD's sigprocmask(2): the calling thread's blocked signals. A FreeBSD sigset_t is four 32-bit words, with signal n at bit n - 1. how is SIG_BLOCK (1), SIG_UNBLOCK (2) or SIG_SETMASK (3), and is ignored when there is no new set. The bundled libc's setjmp (libc.elf+0x2fcb0) reads the mask with SIG_BLOCK and no new set, and its longjmp (libc.elf+0x2fd00) puts it back with SIG_SETMASK.

What the runtime does. No signal is delivered to the guest yet. So the runtime keeps each guest thread's mask, a new thread starting with its creator's, and does not apply it to the host thread.

What stops by name: an unknown how. Its error is reported through the guest's errno, which the runtime does not model.

An executable may declare its main thread's settings in its process parameters (sceUserMainThreadPriority and the like, which homebrew titles define). Without them the main thread runs at SCE_KERNEL_PRIO_FIFO_DEFAULT, 700 (libretro's public ps4_defines.h). The executable passes the same 700 (0x2bc) as a priority to sceUserServiceInitialize. - This executable's block holds no main thread settings: after relocation only the C library's parameter pointer (+0x38) is set, and +0x18 to +0x37 are empty. - Created threads. A thread created without explicit scheduling inherits its creator's priority (FreeBSD libthr's default attribute, PTHREAD_INHERIT_SCHED). The executable sets none.

What the runtime does. It records priorities. The host schedules the threads, so priorities change nothing else.

What stops by name: - main thread settings in the process parameters (which slot is the priority is not established); - a priority outside 256–767; - a missing thread or variable.

clock_gettime and sceKernelClockGettime (libkernel, issue #34)

clock_gettime(clockid_t id, struct timespec *tp) is POSIX, with FreeBSD's clock numbers and amd64 struct timespec (two 64-bit fields, seconds and nanoseconds).

The bundled libc's time() (libc.elf+0x2f030) asks for clock 13 and returns its seconds. Clock 13 is FreeBSD's CLOCK_SECOND, which FreeBSD answers with the wall clock's whole seconds and 0 nanoseconds (kern_clock_gettime).

What the runtime does. It answers the clocks whose meaning FreeBSD fixes and the host has: - CLOCK_REALTIME (0) and CLOCK_SECOND (13), from the host's wall clock; - CLOCK_MONOTONIC (4), from the host's monotonic clock.

What stops by name: other clocks and a missing timespec. Their errors go through errno, which the runtime does not model.

sceKernelClockGettime(id, tp) is the same call under its SCE name. It returns 0x80020000 plus the error number: EINVAL for another clock and EFAULT for a missing timespec, as FreeBSD answers them. The executable's call (0x0111a815) asks for clock 4, and treats anything but 0 as failure.

Process time (sceKernelGetProcessTime, issue #34)

uint64_t sceKernelGetProcessTime(void), as the OpenOrbis homebrew SDK's libkernel.h declares it, is the time since the process started.

Its unit is microseconds. The executable turns it into seconds by dividing by 1,000,000: - at 0x00e4fb6e, through the compiler's multiply by 0x431bde83 and shift by 50; - at 0x0252607e, through a division by the double 1000000.0.

It also seeds a random generator with it (0x00835dba).

What the runtime does. It measures from its own start, on the host's monotonic clock.

Audio job manager start-up (sceAjmInitialize, sceAjmModuleRegister, issue #37)

The audio job manager (libSceAjm) decodes compressed audio in batches of jobs. The OpenOrbis homebrew SDK's Ajm.h names these two calls without signatures, so their shapes come from the executable's only calls: - 0x01118a65: runs while its context variable still holds -1, and passes 0 and the variable's address. A nonzero result is failure. - 0x01118a81: then passes that context, 1 and 0, and again treats nonzero as failure.

What the runtime does. It hands out a context id and records the registered module. Decoding belongs to the batch and instance calls, which stop by name until they are implemented.

What stops by name: - a nonzero first argument to initialize; - a module other than the observed 1 (which codec it names is not public); - a nonzero third argument; - a context the runtime did not hand out; - registering a module twice.

Audio output (sceAudioOutInit, sceAudioOutOpen, sceAudioOutSetVolume, sceAudioOutOutput, issue #37)

The OpenOrbis homebrew SDK's AudioOut.h declares int32_t sceAudioOutInit(void) and int32_t sceAudioOutOpen(user, port type, index, length, sample rate, param). Its _types headers give: - port type 0 (main); - format 4 (float stereo); - the error codes 0x8026000E (already initialized) and 0x8026000F (not initialized).

What the executable does: - Its only init call (0x0111b665) accepts success or exactly 0x8026000E. - Its only open (0x0111b69d) passes user 0xff (the system user in the SDK's user types), the main port, index 0, 256 samples, 48000 Hz and a format. It keeps a non-negative result as the port handle. - The format is the executable's own evidence. Its output callback (0x0111b600) accepts 2 or 8 channels and passes 4 | (channels == 8). So 4 is float stereo (as in the SDK) and 5 is float with eight channels. The boot opens eight channels. - A second open (0x0111b6fc) passes port type 1 with the same settings, and does not check the result. The PS4 name of type 1 is not public; the sibling Vita SDK calls it BGM.

What the runtime does. It records each open port and hands out handles from 1. Sound output belongs to the output calls, which stop by name until they are implemented.

What stops by name: any open other than the observed ones, and running out of handles.

int32_t sceAudioOutSetVolume(handle, flag, int32_t *volume), as the SDK declares it, comes next. The executable's only call (0x0111b6d6) passes its new port, flag 0xff and eight volumes of 32768, and treats nonzero as failure. Flag bit n selects channel n, whose volume is volume[n].

What the runtime does. It records the volumes.

What stops by name: - a handle it did not hand out; - a flag naming a channel the port does not have; - a missing array; - a volume outside 0–32768.

int32_t sceAudioOutOutput(handle, const void *samples), as the SDK declares it, hands a port sound. The executable's audio thread (0x0111b93c) hands its port one block at a time (length samples for every channel). It advances its ring buffer when the result is not negative, and loops with no wait of its own. So the call itself paces the thread: it returns once the port has room for the next block.

What the runtime does. It plays nothing yet. - Each port takes one block per length / rate seconds (256 samples at 48000 Hz: 5.33 ms). - A call waits until the block before it would have finished playing, then answers 0 (the caller only checks the sign). - A port that falls behind starts again from now.

What stops by name: a missing block, and a handle the runtime did not hand out.

int32_t sceAudioOutGetPortState(handle, void *state), as the SDK declares it, reports a port's state. Its _types/audio_out.h gives the layout (32 bytes): a 16-bit output, an 8-bit channel count, a volume and a 64-bit flag. The executable's only call (0x0111bb41) asks about its second port, and reads only output, testing it for 0.

What the runtime does. It plays nothing on the host, so no port is output anywhere. It answers output 0, and 0 in the fields whose encoding is not established. This must change when the runtime plays sound.

What stops by name: an unknown handle, and a missing state.

Attribute priority and CPU mask (scePthreadAttrSetschedparam, scePthreadAttrSetaffinity, issue #34)

scePthreadAttrSetschedparam(attr, const struct sched_param *param) sets the priority (sched_param's one int) of a thread created with the attribute. OpenOrbis' libkernel.h gives the shape; libthr's _pthread_attr_setschedparam gives the semantics.

What the executable does. Its thread wrapper (0x0111aafd) sets it without explicit-scheduling inheritance. So under libthr's default (PTHREAD_INHERIT_SCHED), the new thread still starts at its creator's priority. The wrapper then sets the priority itself with scePthreadSetprio (0x0111ab46).

What the runtime does. It records the priority on the attribute. A variable holding no attribute is EINVAL (libthr).

What stops by name: a missing param, and a priority outside 256–767.

scePthreadAttrSetaffinity(attr, uint64_t mask) is the wrapper's next call (0x0111ab0e), with the CPU mask its caller chose. As for scePthreadSetaffinity, the runtime records the mask (the created thread takes it) and the host schedules. An empty mask stops by name, and a variable holding no attribute is EINVAL.

The title's files: /app0, sceKernelStat, opening and reading (issue #35)

The title reads its own data under /app0, the console's read-only mount of its package. The runtime serves /app0 from your own copy and never writes to it: - tools/boot.py --app0 DIR chooses the copy, defaulting to $BB_APP0, then $BB_DATA_ROOT/merged. - pbboot takes it as --app0. - A path under any other mount, and one with a .. component (which could leave the copy), stops by name.

sceKernelStat(path, struct stat *) is FreeBSD's stat(2) under its SCE name, which returns 0x80020000 plus the error number. The PS4's struct stat is FreeBSD 9's amd64 layout, 120 bytes (OpenOrbis' _types/kernel.h, OrbisKernelStat).

What the executable does. Its call at 0x02474519 asks whether /app0/dvdroot_ps4/sound/sprj_mixer.fev exists: - 0 means yes; - exactly 0x80020002 (ENOENT) means no; - anything else goes to its error path.

What the runtime does. It fills the structure from the host file: - type, size, block count and size, link count and times; - the permission bits without write (the mount is read-only); - device and inode numbers as the host's (they only identify the file); - the birth time as the modification time (the host's stat has none); - owner, group, flags and generation 0.

Errors. A missing file answers ENOENT, and a missing directory component ENOTDIR (the same numbers on FreeBSD and Linux). Any other host error stops by name.

Opening and reading

sceKernelOpen, sceKernelRead, sceKernelPread, sceKernelLseek, sceKernelFstat and sceKernelClose are FreeBSD's open(2), read(2), pread(2), lseek(2), fstat(2) and close(2) under their SCE names. The OpenOrbis homebrew SDK's libkernel.h declares the shapes. Each returns a result, or 0x80020000 plus the error number. The executable opens its data with flags 0 (O_RDONLY) and mode 0555.

What the runtime does: - Opening. It opens the host file read-only. A request to write, create, truncate or append answers EROFS, as FreeBSD does on a read-only mount. The lookup comes first: a missing file without O_CREAT is ENOENT. Other flag bits stop by name. - Descriptors. A descriptor is the runtime's own number, from 3 up, standing for a host descriptor (the title only passes it back). One the runtime did not hand out is EBADF. - Seeking. A whence other than 0, 1 or 2 (SEEK_SET, SEEK_CUR, SEEK_END, the same on FreeBSD and Linux), and a seek before the start, are EINVAL.

Memory protection queries (sceKernelQueryMemoryProtection, issue #34)

sceKernelQueryMemoryProtection(void *address, void **start, void **end, int32_t *protection), as the OpenOrbis homebrew SDK's libkernel.h declares it, gives the protection of the mapping that holds an address.

What the executable does. Its helpers (0x02abad98, 0x02abadf8) pass no start or end. They test the protection's CPU read bit (1) and GPU read bit (0x10), on memory the game mapped itself.

What the runtime does. It records every direct and flexible mapping with the protection the guest asked for, GPU bits included, and answers that.

What stops by name: - a start or end (whether end is inclusive is not established); - an address outside those mappings (other memory is not tracked yet); - a missing variable.

GNM: the tessellation factor ring (sceGnmGetTheTessellationFactorRingBufferBaseAddress, issue #39)

Graphics are rebuilt at the engine level (issue #39), so the GNM calls answer what the engine expects back; the GPU is not emulated.

The OpenOrbis homebrew SDK's GnmDriver.h only names this call. The executable's only call (0x02ad3fb4) takes a 64-bit address and maps 128 KiB of direct memory there, for the GPU's tessellation factors: sceKernelMapDirectMemory with that address as a hint, protection 0x33, alignment 0x10000.

What the runtime does. The PS4 answers a fixed address of its own. The runtime answers one it reserves for this, 0xfe00000000: below 2^40, and clear of the executable, modules and thread objects. It is the runtime's choice, not the PS4's value: the engine only maps it and hands it back to the GPU calls.

For this, sceKernelMapDirectMemory now takes an address hint as FreeBSD's mmap does without MAP_FIXED: the map goes there when the range is free. A hint in use (where the system then maps is not established) and one off the alignment stop by name.

Virtual memory queries (sceKernelVirtualQuery, issue #34)

sceKernelVirtualQuery(address, flags, info *, size), as the OpenOrbis homebrew SDK's libkernel.h and _types/kernel.h (OrbisKernelVirtualQueryInfo) declare it, describes the mapping that holds an address. The answer is a 0x48-byte structure:

Offset Field
0x00, 0x08 start and end
0x10 the direct memory offset
0x18 protection
0x1c memory type
0x20 flag bits: flexible 1, direct 2, stack 4, pooled 8, committed 0x10
0x24 a 32-byte name

What the executable does. Every call passes flags 0 and size 0x48, and reads the start, the offset or the direct bit: - 0x02d0328c works out an address's place in direct memory as offset + (address - start); - 0x02ad3f5e, 0x02ad4066 and 0x02ad423e release the direct memory at the offset.

What the runtime does. It answers from its record of direct and flexible mappings: start, offset, protection as asked for, memory type, flexible or direct, committed, and no name. No call reads the end, and whether it is inclusive is not established; the runtime writes the address just past the mapping.

What stops by name: - flags other than 0; - a size other than 0x48; - an address outside those mappings (other memory is not tracked yet); - a missing structure.

GNM: compute queues (sceGnmMapComputeQueue, issue #39)

OpenOrbis' GnmDriver.h only names this call, so its shape comes from the engine's wrapper (0x01489a80, called from its compute queue setup at 0x0148c7b0).

What the engine does: - The wrapper passes the pipe and queue from the queue object, the ring buffer, its size in dwords, and the address of the GPU's read pointer. - A negative result is failure. Otherwise the wrapper keeps the result as the queue's id, and sets the read pointer to 0. - The setup then reports success only when that id is not 0.

What the runtime does. It does not run the GPU, so the ring is never read. It records each queue for the engine-level graphics layer, and answers ids from 1.

What stops by name: mapping the same pipe and queue twice, and a missing ring or read pointer.

Kernel event queues (sceKernelCreateEqueue, sceKernelWaitEqueue, sceKernelDeleteEqueue, issue #34)

The PS4 kernel is FreeBSD's, whose kqueue delivers struct kevent: ident (64-bit), filter (16-bit), flags (16-bit), fflags (32-bit), data (64-bit) and udata (a pointer), 32 bytes on amd64. The OpenOrbis homebrew SDK's libkernel.h declares create and delete; its _types/kernel.h lists the filters (display -13, graphics core -14, ...).

What the executable does. Right after asking video out for a flip, it waits with room for one event, a variable for how many came back, and no timeout (0x015e41b6, 0x02ad6f26). So the wait blocks until the flip is done.

What the runtime does: - The queue is a list of registrations, added and triggered by the runtime's own event sources (runtime/include/runtime/equeue.h; video out is the first). - A wait returns the triggered events, oldest first, and clears them, so each is reported once per trigger. - An event's flags and fflags are 0: what the PS4 sets there is not established, and no caller reads them.

What stops by name: - a timeout (no call passes one); - deleting a queue a thread is waiting on; - an event array or count that does not fit; - the error values.

Video out (libSceVideoOut, issue #38)

The OpenOrbis homebrew SDK's VideoOut.h declares the calls. Its _types/video.h gives: - the 40-byte buffer attribute: format, tiling mode, aspect, width, height, pitch in pixels; - the 64-byte flip status: flip count, two times, the flip argument, pending counts, current buffer; - flip rates (0: 60 Hz, 1: 30 Hz, 2: 20 Hz) and flip modes (1: vsync, 2: hsync).

What the executable does. It sets video out up twice, in the same order (0x015e488e and 0x02ad61d4): 1. open, with (0, 0, 0, no parameter); 2. flip rate 0; 3. an event queue with a flip event; 4. a buffer attribute (format 0x80000000; 1920 × 1080 in the first); 5. its buffers.

Each frame, it submits a flip with mode 2 and waits on the queue (0x015e419a, then 0x015e41b6). Its other loop (0x02ad6ee9) reads the flip status until the flip argument reaches the frame it submitted.

What the runtime does. It has no display yet. It keeps each port's buffers and status, and an hsync flip completes at once: - the current buffer and flip argument change, and the flip count grows; - the port's flip events are triggered.

The flip event's ident is 0, and its data the flip argument. The PS4's values are not established, and no caller reads them.

What stops by name: - a vsync flip, and other flip modes or rates; - a flip status before the first flip (its initial argument is not established); - other open arguments; - errors.

Implementation rule

Implement the established contract and test the RT_SYSLIB entry through its library and symbol name. Keep target-specific values separate from host values. When an argument, ID, return value, or error case is unknown, fail loudly with the call name and leave the question open; never choose a value to make tools/boot.py advance.
