Runtime call reference

The runtime's own detailed notes on each system call: the evidence, the exact behavior and what stops by name. This page is copied from Paleblood's docs/runtime-syscalls.md every time the wiki syncs, so it always matches the code.

For the reader-friendly explanation of the same calls, start with Runtime system calls.

This page records contracts used to implement small runtime calls in issues #34 and #41. Public standards and manuals describe portable or platform-specific API behavior; they do not by themselves prove every detail of the PS4 implementation. Keep the distinction below, and leave unresolved behavior unresolved until public documentation, our own reverse engineering, or observed behavior settles it.

Evidence in this repository

The runtime registry distinguishes behavior it implements from diagnostics for behavior that is still unknown. RT_SYSLIB entries are callable implementations and count toward coverage; RT_SYSLIB_UNRESOLVED entries remain callable so a reached import can fail with a useful name, but do not count as implemented or as supplied imports in progress reports.

symbols/imports.csv records getpagesize and gettimeofday as imports of eboot from libScePosix; libc.elf imports clock_gettime, getpagesize, getpid, and gettimeofday from libkernel. Import rows establish that the names are required, not their arguments, return values at every call site, or all clock IDs.

The eight hash-verified target images (eboot.elf and the seven modules, tools/check_target.py) all state p_align 0x4000 for every PT_LOAD segment, with p_offset congruent to p_vaddr modulo 0x4000 (the difference is exactly 0x4000 in each; readelf -l prints the headers).

The decompiled frame limiter calls gettimeofday with a null timezone argument. A separate verified clock helper calls sceKernelClockGettime with clock ID 4, named CLOCK_MONOTONIC in that code. This confirms one monotonic clock request in the game; it does not establish every ID passed through the imported clock_gettime wrapper, or that no other ID is used in unexamined code.

The sceKernelGetCompiledSdkVersion contract describes the observed libkernel getter, the runtime's provider of mapped executable process-parameter metadata, and the dedicated synthetic registry tests. It also distinguishes that metadata provider from the unresolved console kernel syscall behavior.

Interfaces and known behavior

Function Arguments and representation Publicly documented result and errors Evidence and open questions for PS4
getpagesize(void) No arguments. Returns the target's page size in bytes. The numeric value is platform-specific. getpagesize is not in current POSIX; portable code is directed to sysconf(_SC_PAGESIZE). Linux and FreeBSD document the byte count; their manuals do not define a general error return for this function. Linux exposes it as a libc interface, not necessarily a dedicated kernel syscall. FreeBSD notes the system page size may differ from the underlying hardware page size. The import is present twice (eboot from libScePosix, libc.elf from libkernel), so both library names are registered against one implementation. The target images bound the value but do not pick one: every PT_LOAD of the eight hash-verified ELFs has p_align 0x4000 with p_offset congruent to p_vaddr modulo 0x4000, and the ELF ABI's congruence rule then limits the system page size to a divisor of 16384 (4096, 8192 or 16384); p_align is the alignment the image requires, not the page size the system reports. Stock FreeBSD on AMD64 uses 4096, and Sony's open-source page confirms the FreeBSD kernel is used but publishes the upstream sources, not the console's modifications, so no public source names the PS4's own value. The runtime entry is therefore registered with RT_SYSLIB_UNRESOLVED, so a boot that reaches it names the call, and it does not count as implemented (runtime/syslib/kernel.c). What would settle it: one observed getpagesize() or sysconf(_SC_PAGESIZE) result on a console, or a guest call site whose page arithmetic shows the granularity the system uses. See the section "getpagesize: observed, inferred, unknown" below; do not hard-code the build host's page size.
getpid(void) No arguments. Returns a pid_t naming the calling process. POSIX specifies that it succeeds and has no error return. Linux process IDs are scoped by PID namespaces; other systems have their own process-ID scope and lifecycle rules. The import is present, but this repository does not establish the guest-visible process ID or its scope. Returning the host PID is not justified by the API contract alone.
clock_gettime(clock_id, tp) clock_id selects a clock; tp points to a struct timespec. On the POSIX interface, tv_sec is seconds and tv_nsec is nanoseconds in [0, 1,000,000,000). The exact target structure layout still needs ABI evidence. POSIX uses 0 for success and -1 with errno for failure. An unsupported clock ID is an EINVAL case. Linux and BSD manuals document additional pointer-error details; use the target contract rather than assuming the host's errno mapping. The imported wrapper is present. The verified sceKernelClockGettime call requests ID 4 (CLOCK_MONOTONIC). That is evidence for the SCE entry point only, not proof of the libc wrapper's IDs. Other IDs and exact PS4 error and pointer handling remain unresolved. Unknown IDs must not silently return a fabricated time.
gettimeofday(tv, tz) tv points to a struct timeval: seconds since the Epoch and microseconds in [0, 1,000,000). The historical timezone argument is passed as null at the confirmed game call site. The exact target structure layout still needs ABI evidence. The wall clock can jump and is not a monotonic elapsed-time source. Historical POSIX specified a zero return on success and left errors undefined; Linux documents -1/EFAULT for inaccessible pointers and ignores the timezone argument. POSIX.1-2024 removed the interface. The imported wrapper and game call sites are present; the game passes null for the second argument. Exact target behavior for bad pointers, non-null timezone arguments, and error mapping is not established. Do not silently ignore an error without evidence.
sched_yield(void) No arguments. Returns int. POSIX: the calling thread gives up the processor until it is again at the head of its thread list; 0 on success, -1 with errno otherwise, and POSIX defines no error case for it. FreeBSD documents the same call. Imported by libc.elf from libkernel. Implemented: a guest thread runs on a host thread, so the runtime yields the host thread and returns 0 (runtime/syslib/kernel_thread.c). A host failure has no FreeBSD error number to report, so it stops by name. Not observable in a unit test: that the host scheduler actually ran another thread.
scePthreadYield Asks for the same yield through the thread library. The PS4-visible signature is not established. FreeBSD's pthread_yield(3) is void; Linux's is int (always 0). No PS4-specific public source gives the SCE name's declaration. Imported by eboot and libc.elf from libkernel; no call site in this repository shows whether the caller reads a result. Registered with RT_SYSLIB_UNRESOLVED: the entry stops by name and does not count as implemented. What would settle it: a guest call site showing whether the return register is read after the call, or a PS4-specific public declaration. Do not assume an int or 0 from the FreeBSD or Linux analogues.
memcpy(dest, src, n), memset(dest, c, n) (libSceLibcInternal) void *memcpy(void *, const void *, size_t) and void *memset(void *, int, size_t), the ISO C declarations. ISO C 7.24.2.1 and 7.24.6.1: memcpy copies n bytes from src to dest; memset writes c converted to unsigned char into the first n bytes; both return dest. Overlapping memcpy regions and null pointers are undefined behaviour. Imported by libSceFios2.elf from libSceLibcInternal (symbols/imports.csv). Implemented with the host's own functions, since the standard fixes the whole result and no target-specific value is involved (runtime/syslib/kernel.c). Not modelled: what the PS4 C library does for the undefined cases; no public source or call site establishes it.
sceKernelUsleep(microseconds) (libkernel), usleep(microseconds) (libScePosix) One unsigned 32-bit count of microseconds, returning int. For sceKernelUsleep the guest fixes the shape: the verified call sites in game/frame_timing/frame_limiter.cpp and game/render/swap_chain_present.cpp declare it as int(uint32_t microseconds), and their cases expect 0. FreeBSD's useconds_t is 32-bit unsigned. FreeBSD usleep(3): suspends the thread for the given microseconds, 0 on success, -1 with EINTR if a signal interrupts it. SUSv2 also let usleep fail with EINVAL from 1,000,000 on; FreeBSD and POSIX.1-2008 (which removed usleep) have no such limit. sceKernelUsleep is imported by eboot and libSceFios2.elf, usleep by eboot. Implemented: the host thread sleeps at least the requested time and the call returns 0; a host signal is not a guest event, so the sleep resumes with the time left (runtime/syslib/kernel.c). Open: usleep with 1,000,000 or more, which stops by name because no PS4-specific source says whether the guest sleeps or gets EINVAL; and the SCE error, if any, for sceKernelUsleep, which the guest's sites never check.
sleep(seconds) (libScePosix) One unsigned count of seconds, returning unsigned int: unsigned sleep(unsigned seconds) in POSIX and FreeBSD's sleep(3). No call site in the repository fixes the shape further. POSIX: suspends the thread until the seconds have elapsed or a caught signal arrives; returns 0 when the time has elapsed, otherwise the unslept seconds; no errors are defined. FreeBSD's libc (lib/libc/gen/sleep.c) is a nanosleep that rounds the unslept remainder up to whole seconds; above INT_MAX it sleeps INT_MAX seconds and returns seconds - INT_MAX without any signal. Imported by eboot. Implemented: the host thread sleeps at least the requested seconds and the call returns 0; a host signal is not a guest event, so the sleep resumes with the time left, as for usleep (runtime/syslib/kernel.c). Open: more than INT_MAX seconds, which stops by name because POSIX has no early return without a signal and no PS4-specific source says whether the guest gets the full sleep or FreeBSD's remainder.
nanosleep(rqtp, rmtp) (libkernel) int nanosleep(const struct timespec *rqtp, struct timespec *rmtp) in POSIX and FreeBSD's nanosleep(2), with FreeBSD amd64's struct timespec (two 64-bit fields, seconds and nanoseconds), the layout the clock_gettime entry uses. No call site in the repository fixes the shape further. POSIX: suspends the thread until the requested time has elapsed and returns 0; a caught signal returns -1 with EINTR and writes the time left through a non-null rmtp; nanoseconds outside [0, 1,000,000,000) are -1 with EINVAL; rqtp and rmtp may point to the same object. A negative second count is not defined. FreeBSD's kern_time.c (same in stable/9 and main): the EINVAL check first, then a zero or negative time returns 0 at once without sleeping; nanosleep(2) adds EFAULT for a pointer it cannot use. Imported by libc.elf. Implemented: the host thread sleeps at least the requested time and the call returns 0; a host signal is not a guest event, so the sleep resumes with the time left and rmtp is never written, as for usleep and sleep; the request is copied first, so rqtp and rmtp may be the same (runtime/syslib/kernel.c). Stops by name: the errno cases (no rqtp, nanoseconds out of range), since errno is not modelled, as for clock_gettime. Open: a negative second count, which stops by name because POSIX does not define it, FreeBSD returns 0 at once and the host answers EINVAL, and no PS4-specific source says which answer the guest gets.
scePthreadRwlockInit(rwlock, attr, name), scePthreadRwlockDestroy(rwlock), scePthreadRwlockRdlock(rwlock), scePthreadRwlockWrlock(rwlock), scePthreadRwlockTryrdlock(rwlock), scePthreadRwlockTrywrlock(rwlock), scePthreadRwlockUnlock(rwlock) (libkernel) A pointer to the guest's rwlock variable (Init also an attribute pointer and a name, as scePthreadMutexInit); each returns int32_t. No call site in this repository shows these shapes; they come from the public OpenOrbis libkernel.h declarations, supporting evidence for the shapes only, and match FreeBSD's pthread_rwlock_*. POSIX pthread_rwlock_*, as FreeBSD libthr (thr_rwlock.c) and the kernel's umtx read-write lock (kern_umtx.c) implement it: a static initializer (NULL) set up on first use and a destroyed rwlock holding 1 (thr_private.h); EINVAL for a destroyed rwlock; EBUSY from the try forms when the lock is not available; destroying does not check whether the lock is held, and leaves an unused initializer in place; unlocking is EPERM when another thread holds the write lock or when nobody holds the lock, and readers are counted, not named; a thread that locks again while holding the write lock is not given an error, it waits forever (no owner check in do_rw_wrlock or do_rw_rdlock). The SCE name returns 0x80020000 plus the error number. Imported by eboot and libSceFios2.elf (Tryrdlock by libSceFios2.elf only; symbols/imports.csv). Implemented on a host rwlock that also records the writer and the reader count, which the host does not expose, for the unlock answers (runtime/syslib/kernel_rwlock.c). A missing variable answers EINVAL, as the mutex calls do; unlocking a never-used initializer is EPERM, as for the mutex. Stops by name: Rdlock or Wrlock while the caller holds the write lock (the system would wait forever, the host answers EDEADLK; neither is useful to return), and an attribute object passed to Init (no imported call creates one, so its contents are not established; an empty attribute variable means the defaults, as in libthr). scePthreadRwlockTimedrdlock and Timedwrlock are under Timed locks. Not part of this entry: the libScePosix names.
__stack_chk_fail(void) (libkernel) No arguments, no result: void __stack_chk_fail(void), and it never returns (LSB; FreeBSD libc declares it __dead2). Compiler-generated code calls it, not application code. LSB Core: the function that called it is aborted with a message that a stack overflow was detected, and the program then exits. FreeBSD libc logs "stack overflow detected; terminated" and ends the process with SIGABRT. Imported by eboot, libSceFios2.elf and libc.elf from libkernel (symbols/imports.csv). Implemented as a stop by name (rt_fatal, which aborts): ending the program is the whole guest-visible contract, so the entry counts as implemented (runtime/syslib/kernel.c). Not covered: the PS4's own message or crash report, which the guest cannot observe after it ends; and __stack_chk_guard, a separate data import whose PS4 value is not established (an unbound data import gets a zeroed page, runtime/boot.c).
_exit(status) (libkernel) One int, no result: void _exit(int status), and it never returns (POSIX; FreeBSD's _exit(2) has the same shape and declares it __dead2). No call site in the repository fixes the shape further. POSIX: the process ends at once; functions registered with atexit are not called and open streams are not flushed; the low 8 bits of status (status & 0377) are available to the waiting parent, and the full value to waitid and SIGCHLD handlers. FreeBSD _exit(2): the same, the C library's exit(3) runs the atexit handlers and flushes, then calls _exit. Imported by libc.elf from libkernel (symbols/imports.csv). Implemented: the host's _exit with the guest's status, which has the same contract (runtime/syslib/kernel.c). Under the boot harness, rt_exit_observer records the run's outcome first, as rt_fatal_observer does for a stop: pbboot reports "exited with code" and the full status, from any guest thread, and still writes the boot record (runtime/boot.c). Not covered: what the PS4 shows the player when a game ends this way, which the guest cannot observe after it ends.
scePthreadCondInit(cond, attr, name), scePthreadCondDestroy(cond), scePthreadCondSignal(cond), scePthreadCondBroadcast(cond), scePthreadCondWait(cond, mutex), scePthreadCondTimedwait(cond, mutex, microseconds) (libkernel) Pointers to the guest's cond and mutex variables; each returns int32_t. The guest fixes the wait shapes: the verified game/kernel/condition_wait.cpp declares Wait as int32_t(void *cond, void *mutex) and Timedwait as int32_t(void *cond, void *mutex, uint32_t timeout_us), a relative timeout in microseconds, not POSIX's absolute timespec. The public OpenOrbis libkernel.h declares all six with these shapes (Init with an attribute pointer and a name, as scePthreadMutexInit); it is supporting evidence for the shapes only. POSIX pthread_cond_*, as FreeBSD libthr implements it (thr_cond.c): a static initializer (NULL) set up on first use; a destroyed cond holds 1 (thr_private.h); EINVAL for a destroyed cond; EBUSY to destroy one with waiters; destroying an unused initializer succeeds and leaves it in place; EPERM when the waiter does not own the mutex, for every mutex type, EINVAL when the mutex is destroyed (_mutex_owned, thr_mutex.c); ETIMEDOUT when a timed wait expires; a recursive mutex is released completely for the wait and its count restored after (_mutex_cv_unlock, _mutex_cv_lock). The SCE name returns 0x80020000 plus the error number. scePthreadCondWait and Timedwait are imported by eboot, libSceFios2.elf and libc.elf, the other four by libSceFios2.elf and libc.elf (symbols/imports.csv). The guest's call site checks exactly 0x80020001 (EPERM), 0x80020016 (EINVAL) and 0x8002003c (ETIMEDOUT). Implemented on a host cond on the monotonic clock (runtime/syslib/kernel_mutex.c): the timed wait times out once the given microseconds have passed since the call (0: at once). A missing cond or mutex variable answers EINVAL, as the mutex calls do. Stops by name: an attribute object passed to Init (no imported call creates one, so its contents are not established; an empty attribute variable means the defaults, as in libthr). A wait with a recursive mutex releases every level the caller holds and takes them back after, as libthr does: the runtime tracks each recursive mutex's owner and depth, and releases the extra levels itself around the host wait. A wait with a mutex the caller does not own is EPERM for every type, as in libthr (see Mutex ownership). Open: a woken waiter counts until it has taken the mutex back, so a destroy right after a broadcast can answer EBUSY while libthr's succeeds; no known call site destroys a cond that way. The libScePosix names pthread_cond_init, _destroy, _signal, _broadcast and _wait (imported by eboot) are the same calls with errno values: the executable's call at 0x0247e6d7 passes (&cond, NULL) and its caller compares the result with bare error numbers (12, 16, 34, 35). pthread_cond_timedwait(cond, mutex, abstime) (imported by eboot; no call site in the repository) takes an absolute time in FreeBSD amd64's struct timespec, the two 64-bit fields of the clock_gettime entry, measured on the cond's clock: CLOCK_REALTIME unless an attribute set another (POSIX pthread_cond_timedwait; libthr's cond_init for no attribute). No imported call can set another: nothing imports pthread_condattr_*, and an attribute object stops Init by name. libthr's pthread_cond_timedwait answers EINVAL before touching the mutex for no time, negative seconds and nanoseconds outside [0, 1,000,000,000); POSIX names only the nanoseconds case and leaves the other two undefined, and the runtime answers all three as libthr does. Implemented: the wait ends at the monotonic deadline where the wall clock reaches the time, the wall clock read first so it is never early; a time already passed is ETIMEDOUT with the mutex taken back. Open: a change of the wall clock during the wait is not followed, which POSIX's CLOCK_REALTIME wait would do.
scePthreadKeyCreate(key, destructor), scePthreadKeyDelete(key), scePthreadGetspecific(key), scePthreadSetspecific(key, value) (libkernel) A key is a pthread_key_t, an int on FreeBSD (sys/_pthreadtypes.h); Create takes a pointer to the guest's key variable and a destructor (void (*)(void *), may be null), Getspecific returns void *, the others int32_t. These shapes come from the public OpenOrbis libkernel.h, supporting evidence for the shapes only, and match FreeBSD's pthread_key_create, pthread_key_delete, pthread_getspecific and pthread_setspecific. POSIX thread-specific data, as FreeBSD libthr implements it (thr_spec.c, the same in stable/9): a key is its slot's index plus 1, and Create takes the first free slot; Delete of a key that is out of range or free is EINVAL and calls no destructor; Setspecific of such a key is EINVAL, Getspecific answers NULL, as it does for a key the thread has not set since the key was created (each slot counts its creations). When a thread ends, each non-null value is cleared and, if its key is still the one it was set under, the destructor is called with it, in rounds while values remain (_thread_cleanupspecific). The SCE name returns 0x80020000 plus the error number. Imported by libc.elf from libkernel (symbols/imports.csv). Implemented with the runtime's own key table and a host thread-local value array per guest thread (runtime/syslib/kernel_key.c); a thread created by scePthreadCreate runs its destructors on its guest stack when its entry returns (runtime/syslib/kernel_thread.c). A missing key variable for Create (unchecked in libthr) answers EINVAL, as the mutex calls do. Not established: the PS4's number of keys and of destructor rounds. POSIX guarantees at least 128 keys (_POSIX_THREAD_KEYS_MAX) and 4 rounds (_POSIX_THREAD_DESTRUCTOR_ITERATIONS), FreeBSD gives 256 and 4 (<pthread.h>); the runtime gives what POSIX guarantees and stops by name past it: a 129th live key, and a thread whose destructors still leave values after the 4th round. The main thread's values get no destructors, since it never ends through a thread exit here.

scePthreadAttrGetaffinity: the startup consumer and missing evidence

An affinity mask identifies the CPUs on which a thread may run. The current startup stop is a query for the main thread's mask. Returning success without the correct output would change the CPU count that the bundled C library stores; it would not implement the query.

Observed in the hash-pinned bundled libc.elf: the function at module offset 0x81a80 initializes a thread attribute, obtains the current thread, and copies its attributes. If those operations succeed, its call at libc.elf+0x81ad0 passes the address of that attribute variable in RDI and the address of a zero-initialized eight-byte stack slot in RSI. This is a two-pointer interface, not FreeBSD's three-argument interface with an explicit buffer size. The return site is libc.elf+0x81ad5, matching the genuine boot diagnostic. The caller does not check the affinity query's return value: after destroying the attribute it reads the slot, counts its set bits across 64 bits, and stores a 32-bit count. This establishes the consumer's memory requirements, not the real query's write width, the actual mask or its complete error contract.

The original consumer also ran through the existing harness on nine private constructed fixtures with scripted imports, using each compiler's loader. It produced the expected counts for zero, low-bit, high-bit and all-bit masks, and exercised both earlier failure branches. A scripted nonzero affinity return with a supplied mask still produced that mask's count, corroborating that this caller ignores the return. These are original-consumer observations under synthetic import behavior, not observations of PS4 affinity, recorded gameplay, complete instruction-trace verification or an original-versus-replacement comparison. No function status changes follow from them.

Public supporting evidence: the OpenOrbis homebrew header libkernel.h declares a signed 32-bit return and an attribute pointer plus an output pointer. Its comment explicitly leaves the mask type unfinished; the declaration is corroboration, not a measured PS4 contract. The FreeBSD 9.3 affinity manual describes retrieving a stored attribute mask, success/error returns and invalid attributes, but its API includes a size argument absent at this target call. Its errors and CPU-set layout cannot simply be assigned to the SCE interface.

Still required before implementation: independently establish the main thread's actual mask, how a fresh attribute differs from one filled by scePthreadAttrGet, the exact output write extent, success/error results, and invalid/null attribute or output handling. Host CPU availability and a guessed console core count establish none of these. No specific affinity implementation is added or registered by this investigation; the import remains unbound.

A useful target measurement would record the console/firmware and executable identities, the results of attribute initialization and copying from scePthreadSelf, the getter's return bits, the output bytes with adjacent canaries, and repeated observations without changing affinity. Check current claims in issue #34 before taking implementation work; mentions of the boot blocker are not themselves contributor claims. Generic gameplay capture remains separate contributor-owned work, not a reason to synthesize the missing affinity observation.

How the boot gets past it without a value. These are observations from static analysis of the hash-pinned eboot.elf, libc.elf and libSceFios2.elf (Ghidra 12.0.3 with GhidraOrbis, issue

34), not guarantees:

  • The probe's count is stored at libc.elf+0xd1c54. That lies past the RW segment's file size, so it starts zero.
  • The probe returns nothing. It is reached only by a tail jump from the initializer at +0x5fad0, which the module's DT_INIT runs.
  • The count's only reader found is the exported std::thread::hardware_concurrency() at +0x5fac0.
  • No reference to that function was found in those three objects, none of them imports it, and none imports sceKernelDlsym.

So game/module_hooks.csv replaces two functions before any guest code runs: - the probe (+0x81a80, 128 bytes) with return, so the affinity query is never made and the count stays zero; - hardware_concurrency (+0x5fac0, 7 bytes) with stop, so a caller ends the run by name instead of reading a count nobody established.

Clock IDs and platform differences

The only clock ID confirmed by a decompiled game call in this repository is 4, used with sceKernelClockGettime and identified there as CLOCK_MONOTONIC. This does not prove that the game passes 4 to the imported clock_gettime wrapper. POSIX defines clock identifiers symbolically; their numeric values are implementation-specific. Linux adds clocks such as CLOCK_MONOTONIC_RAW and CLOCK_BOOTTIME; FreeBSD has its own clock set, including CLOCK_UPTIME variants. Their names and numeric values are not interchangeable evidence for PS4 behavior.

CLOCK_MONOTONIC represents elapsed time from an unspecified starting point and is not the wall clock. The precise effects of suspend, rate correction, and resolution vary by implementation. gettimeofday and CLOCK_REALTIME represent wall time tied to the Epoch and can move when system time changes. No source examined here establishes that the game asks the imported clock_gettime wrapper for CLOCK_REALTIME, CLOCK_MONOTONIC_RAW, CLOCK_BOOTTIME, or another ID.

Network byte-order helpers

The four libSceNet imports sceNetHtonl, sceNetHtons, sceNetNtohl, and sceNetNtohs take and return 32-bit or 16-bit unsigned integers, respectively. Public PSP2SDK API declarations provide those widths for the SCE names. The standard byte-order contract converts host order to network (big-endian) order for hton*, and reverses that conversion for ntoh*; this is documented by the FreeBSD byte-order manual. Paleblood's guest ABI is AMD64, so these four conversions are byte reversals. Their implementations do not call host networking APIs or depend on host socket state.

This evidence supports only the four integer conversions. It says nothing about libSceNet socket, resolver, epoll, offline-state, or error behavior; those imports remain unresolved until their own contracts are established.

getpagesize: observed, inferred, unknown

Observed in our target (read-only; the eight images verify against target.sha256 and target.image.sha256):

  • symbols/imports.csv has exactly two getpagesize rows - eboot from libScePosix and libc.elf from libkernel. No sysconf and no quad-page call is imported, so this is the only page-size query the guest has.
  • All sixteen PT_LOAD segments of those eight images have p_align 0x4000, and in every one p_offset - p_vaddr is exactly 0x4000.
  • Three guest call sites share one shape: 0x00e04168, 0x00e04939 and 0x00e05cf9, each inside functions 0x00e04140, 0x00e045c0 and 0x00e05a80. Each is a lazy initialiser: a guard tests 0x05859ec0, the call is made, the result is cltq-extended, blsr %rax,%rcx with jne rejects it unless it is a power of two, and the value is cached in 0x05859ec8 beside three fixed siblings (0x10000, 0x40000, 0x200000).
  • 0x05859ec8 has exactly five cross-references in the executable: the three writes above and two reads, all inside those same three functions. None of them compares the cached value against a constant, and no other function reads it.

Inferred, and the premise each inference needs:

  • The ELF ABI takes p_align of a loadable segment to be a multiple of the system page size, and requires p_offset and p_vaddr to be congruent modulo the page size. If the PS4 loader follows both rules for these segments, a page size larger than 0x4000 could not map them at their fixed addresses, while any power-of-two divisor of 0x4000 could.
  • Restricting that to 0x1000, 0x2000 and 0x4000 adds a second assumption - that the page size is at least 4096 - which is ours, not observed. The guest's own blsr check is consistent with every power of two and selects none of them.
  • So p_align bounds the candidate set under our premises; it does not measure the value the kernel returns, and none of the three candidates is established.

Unknown: the number the PS4 reports. Stock FreeBSD on AMD64 uses 4096 (PAGE_SHIFT 12, sys/amd64/include/param.h), and Sony's open-source page confirms a FreeBSD kernel but publishes the upstream sources rather than the console's modifications, so that value describes the ancestor and not the target. Our own loader does not depend on a page size either: it copies PT_LOAD segments at byte-exact p_vaddr into one image buffer (runtime/loader.c, rt_elf_map) and uses p_align only for TLS, and the 4096s in runtime/boot.c are host allocation sizes. What would settle it: one observed getpagesize() or sysconf(_SC_PAGESIZE) result on a console.

Thread attribute detach state (scePthreadAttrSetdetachstate, issue #34)

eboot and libSceFios2.elf import scePthreadAttrSetdetachstate from libkernel, and eboot imports pthread_attr_setdetachstate from libScePosix (symbols/imports.csv). Each source below establishes a different part:

  • What the call does: POSIX pthread_attr_setdetachstate. A thread created with the attribute starts detached for PTHREAD_CREATE_DETACHED and joinable for PTHREAD_CREATE_JOINABLE.
  • Invalid detach state: POSIX and FreeBSD's pthread_attr(3) both make any other value EINVAL.
  • Invalid attribute variable: POSIX leaves a null or uninitialised attribute undefined and only recommends EINVAL, and the FreeBSD manual lists no error for it. The behaviour comes from FreeBSD libthr's _pthread_attr_setdetachstate (lib/libthr/thread/thr_attr.c), which returns EINVAL when the variable is null or holds no attribute object.
  • The numbers: FreeBSD's <pthread.h> defines the two states as 0 and 1. The OpenOrbis homebrew SDK header (include/orbis/_types/pthread.h) defines ORBIS_PTHREAD_CREATE_JOINABLE and ORBIS_PTHREAD_CREATE_DETACHED with the same values. That header follows FreeBSD's text, so it corroborates the numbers rather than measuring them independently.

As with the mutex functions (runtime/syslib/kernel_mutex.c), the SCE name returns 0x80020000 plus the error number, and the POSIX name returns the number itself.

Still open: the detach state a fresh attribute starts with, and the one scePthreadAttrGet copies from a running thread. Both are values the system supplies. POSIX makes joinable the default, but nothing we can cite confirms what the PS4 reports. In FreeBSD libthr, _pthread_create (thr_create.c) uses that same default (_pthread_attr_default) when it is given no attribute variable or an empty one. The runtime treats both cases as the unknown default, so the outcome, a fatal, does not depend on the PS4 matching libthr there.

How the runtime keeps that open:

  • The attribute records a state only when one is set (has_detach_state). scePthreadAttrGet replaces the whole attribute, as libthr's pthread_attr_get_np does, so a state set before the copy is dropped.
  • By convention, thread creation reads the state through rt_thread_attr_detach_state (runtime/include/runtime/process.h) and never from the field. A fresh attribute's field holds zero, which is the joinable value, so reading the field directly would assume joinable silently.
  • For no variable, an empty variable, or a state nobody set, the reader stops the process (rt_fatal), names the call that asked, and says which of those cases it hit.

What would settle it: an observed scePthreadAttrGetdetachstate result on a console, for a fresh attribute and for one filled by scePthreadAttrGet from the main thread. Guest call sites would also settle it: a thread created without a detach state being set, then joined or detached (scePthreadJoin, pthread_join and scePthreadDetach are imported).

Mutex ownership (scePthreadMutexUnlock, issue #132)

A mutex belongs to the thread that locked it. FreeBSD libthr (thr_mutex.c, the same in stable/9 and main) checks that for every mutex type:

  • Unlocking a mutex the caller does not own is EPERM, whether it is free or another thread holds it (mutex_unlock_common); so is a condition wait with it (_mutex_owned).
  • The owner locking again gets EDEADLK for the error-checking (default) and adaptive types, and waits forever for the normal type, on purpose (mutex_self_lock). Its trylock is EBUSY for all three (mutex_self_trylock). A recursive mutex counts one more level.

The host (glibc) checks the owner only for its error-checking and recursive types, and its adaptive type waits forever when the owner locks again. So the runtime makes every non-recursive guest mutex an error-checking host mutex, and keeps the guest type for its own answers (runtime/syslib/kernel_mutex.c):

  • scePthreadMutexUnlock, pthread_mutex_unlock and the condition waits answer EPERM for a caller that does not own the mutex, for the normal and adaptive types too.
  • The adaptive type locked again by its owner answers EDEADLK, as in libthr.
  • The normal type locked again by its owner stops by the name the guest used (scePthreadMutexLock or pthread_mutex_lock): the system would wait forever, the host answers EDEADLK, and neither is useful to return.

The SCE names return 0x80020000 plus the error number, the libScePosix names the number itself. One difference left: the adaptive type no longer spins before it sleeps, as libthr's and glibc's do; that changes timing only, not an answer.

Timed locks (scePthreadMutexTimedlock, scePthreadRwlockTimedrdlock, scePthreadRwlockTimedwrlock, issue #34)

Each takes the lock variable and the most it may wait, in microseconds from now (OpenOrbis libkernel.h declares an OrbisKernelUseconds; shadPS4 binds the three names to libthr's relative-time calls, pthread_mutex_reltimedlock_np and pthread_rwlock_reltimed*lock_np, facts only). The executable's lock wrappers take them for any timeout but -1, which uses the untimed call: 0x02484119 (mutex) tells EDEADLK, EINVAL, EAGAIN and ETIMEDOUT apart, and 0x0247f681 and 0x0247f411 (rwlock) EDEADLK, EINVAL and ETIMEDOUT.

What the runtime does: - The wait ends with the lock, or with ETIMEDOUT once the time has passed, on the monotonic clock (as for scePthreadCondTimedwait). - The owner asking again. With a timeout, libthr's mutex_self_lock sleeps the whole time and answers ETIMEDOUT for the error-checking, adaptive and normal types; a recursive mutex takes one more level. The kernel's umtx rwlock has no owner check, so a thread holding the write lock that asks again waits out the time too (do_rw_rdlock, do_rw_wrlock). The host would answer EDEADLK at once, so the runtime sleeps the time itself. - A destroyed lock or a missing variable is EINVAL, and the static initializers are set up on first use, as for the untimed calls.

Direct memory (libkernel, issue #34)

eboot imports sceKernelGetDirectMemorySize, sceKernelAllocateDirectMemory, sceKernelMapDirectMemory and sceKernelReleaseDirectMemory (symbols/imports.csv). Its first use is the startup heap, at 0x02481a80:

  1. It asks for the size.
  2. It allocates 0x7400000 bytes, aligned to 0x200000, anywhere from 0 to that size, with memory type 0.
  3. It maps the range read/write (protection 3) with flags 0, so the system picks the address, at the same alignment.
  4. If the map fails, it releases the range.
  5. On any failure it logs an error and builds its heap from a null base, so these calls have to succeed.

  • GPU access. The executable maps with protection 3 and 0x33, CPU and GPU read/write (0x10 and 0x20 in the public SDK list). The host mapping takes the CPU bits.
  • Where a map goes. Without an address hint, the system chooses:
  • A GPU-visible map goes at a fixed base (0x2000000000) plus its offset in the pool. Every such address is then a fixed distance from the same byte of the pool, which is how the renderer's GPU will reach guest memory: it gets the whole pool as one buffer (runtime/gpu_memory.h, docs/RENDERER.md).
  • Other maps go anywhere free in the map window above that region.
  • A second GPU-visible map of a range would need the same place, so it stops by name. A boot doesn't make one: every range it maps, it maps once.
  • With a hint, a map goes where the hint says (below).
  • What stops by name. Every case whose PS4 answer is not established stops with the function's name:
  • lengths, starts or alignments that are not multiples of 16 KiB (the granularity the executable's calls use);
  • memory types other than 0, 3 and 10;
  • map flags other than no-overwrite (0x80, shadPS4's kernel memory.h). No-overwrite keeps a map off memory already mapped, and the runtime never replaces a mapping, so it changes nothing. The movie code (0x02d032b9) passes it with no address, to map part of its own direct memory a second time;
  • protection other than CPU and GPU read and write;
  • a range that does not fit or was not allocated;
  • releasing part of a range or a mapped one;
  • the error values.

Measured with a local boot that let the libc affinity probe return (not committed): with these four calls the executable's heap setup succeeds and the boot reaches entry. It stops next at scePthreadRwlockInit.

Range arithmetic

The existing sceKernelAllocateDirectMemory and sceKernelMapDirectMemory implementations validate lengths by subtraction after checking the starting address. This prevents a full-width length from wrapping an end address and passing the allocation or containment check. An allocation must fit wholly inside its end-exclusive search range; a map must fit inside one live allocation. Misaligned address hints still stop by the API name before mapping.

test_direct_memory_bounds exercises the registered calls with exact boundaries, overlong and wrapping ranges, a misaligned hint and a valid writable map. These are host validation limits, without a claim about native error codes.

Kernel semaphores (libkernel, issue #34)

eboot imports sceKernelCreateSema, sceKernelDeleteSema, sceKernelWaitSema, sceKernelSignalSema and sceKernelPollSema (symbols/imports.csv). Its own calls are the evidence here. They include the audio wrappers at 0x0111ad10–0x0111adc0 and the wrappers at 0x0084ac20–0x0084ac83:

  • Create: (&handle, name, attr, initial, max, NULL), with attr 1 or 2, initial 0 or passed through, and max 0xffff, 1, or passed through.
  • Wait: (handle, 1, NULL), with no timeout.
  • Signal: (handle, 1) or a count passed through.
  • Delete: (handle).
  • Results: every result is compared with 0.

The signatures, and attr 1 = FIFO and 2 = priority wake order, match the OpenOrbis homebrew SDK headers (supporting evidence only).

What the runtime does. A semaphore is a runtime object behind the handle. Wait blocks until the units are there. Waiters are served in the order they arrived, or with attr 2 by thread priority: - the best priority goes first, which is the smallest number (OpenOrbis _types/user.h: 0x100 highest, 0x2FF lowest); - equal priorities are served in arrival order; - each waiter is placed by the priority its thread has when it starts to wait. The runtime records each guest thread's priority (scePthreadSetprio, inherited at creation).

shadPS4's semaphore (threads/semaphore.cpp) orders its wait list the same way. Signal adds units and wakes the waiters.

What stops by name. Every case whose PS4 answer is not established stops with the function's name: - timeouts; - a missing semaphore, variable or name; - an option parameter, and attributes other than 1 and 2; - counts outside 0 <= initial <= max; - signalling past the maximum; - a poll that cannot be satisfied now; - deleting a semaphore with waiters; - a wait for more than one unit behind another waiter (whether it may be passed is not established); - the error values.

A local boot that let the affinity probe and the rwlocks through (not committed) stopped next at sceKernelCreateSema. With throwaway answers past it, the next stops were gettimeofday, then sceSysmoduleLoadModule for system module 0x00b4.

Ending a thread (scePthreadExit)

scePthreadExit(void *value) ends the calling thread with value, as a return from its entry would: the value kept for a join, then the thread's key destructors, then the end (FreeBSD libthr's _pthread_exit, and shadPS4's posix_pthread_exit).

The runtime does not unwind the guest's frames, which were not built for the host's unwinder. Instead the thread's host side marks where it starts the guest's entry (setjmp), and an exit returns there (longjmp). It then ends exactly as a return does.

Stops by name: an exit from inside a key destructor (libthr refuses it too), and an exit from the main thread, which the runtime runs the boot on.

Thread attributes: stack size and scheduling policy (issue #34)

The executable's thread wrapper (0x02a3b324–0x02a3b46e) sets up each thread like this:

  1. It initializes an attribute.
  2. It sets the stack size: the caller's size, or 64 KiB by default. If that is refused, it retries with 16 KiB and reports a fatal error if that fails too.
  3. It sets detach state 0 and scheduling policy 1.
  4. It creates the thread with (&thread, &attr, entry, argument, name), comparing a failure with EPERM, EINVAL and EAGAIN as SCE codes.
  5. It destroys the attribute and sets the new thread's affinity to a mask of the six bits 0x3f.

What the runtime does:

  • scePthreadAttrSetstacksize and pthread_attr_setstacksize record the size. The stack's address is left to the system, as libthr keeps one address and size per attribute.
  • Sizes below 16 KiB are refused with EINVAL. libthr refuses sizes below its minimum that way, and the executable's wrapper names the PS4's minimum: its callers pass smaller sizes, and when one is refused it asks again for exactly 16 KiB (0x02a3b383).
  • scePthreadAttrSetschedpolicy records one of FreeBSD's three policies (FIFO 1, OTHER 2, RR 3). libthr refuses any other with ENOTSUP, whose SCE value is not established, so another policy stops by name.
  • A missing attribute answers EINVAL (as an SCE code under the SCE names).

Thread creation (scePthreadCreate, scePthreadSetaffinity, issue #34)

scePthreadCreate(&thread, &attr, entry, argument, name) runs the guest on a new host thread:

  1. The thread gets its own guest stack, of the attribute's size.
  2. It gets its own TLS block, a copy of the executable's template as the main thread's is, and its thread pointer goes in GS.
  3. It is registered, so scePthreadSelf answers the new thread's handle.
  4. entry(argument) is called with the guest's convention. A return ends the thread (POSIX).
  5. The attribute's detach state decides whether the host thread is joinable.

The scheduling policy is recorded, but the host schedules the thread: guest priorities are not modelled.

What stops by name: - no attribute, or no stack size or detach state on it (the PS4 defaults are not established); - a stack address the guest supplies; - the error values.

scePthreadSetaffinity records the CPU mask. The executable sets it once per thread, within 0x3f. Scheduling is left to the host, because the host's CPUs say nothing about the PS4's. An empty mask stops by name.

Stops on other threads. A worker thread can fault or reach an unimplemented import. The boot records the first such stop and wakes the main thread (SIGUSR1) to make the usual report. Workers leave the timeout and that signal to the main thread.

A local boot with the affinity probe and the rwlocks let through (not committed) reaches the threads milestone and stops next at sceUserServiceInitialize.

Joining, detaching, explicit scheduling and once (issue #34)

scePthreadJoin(thread, void **value) and scePthreadDetach(thread) are FreeBSD libthr's pthread_join and pthread_detach (thr_join.c, thr_detach.c; OpenOrbis libkernel.h shapes; shadPS4's JoinThread and posix_pthread_detach agree, facts only). The executable's join (0x02a3b6c5) tells ESRCH, EDEADLK and EINVAL apart. The other callers compare the answer with 0: libc.elf +0x6130 and +0x6174, libSceFios2 +0x2ebde, and the POSIX pthread_join (libScePosix) at 0x00838793 and 0x008387f3.

In libthr's order: - join: no thread is EINVAL; the calling thread itself EDEADLK; a thread the runtime does not know, or one already collected, ESRCH; a detached thread EINVAL; a thread another thread waits to join ENOTSUP (45). Otherwise it waits for the end, stores the exit value through a non-null value, and collects the thread. - detach: no thread is EINVAL; an unknown or collected thread ESRCH; a detached thread, or one a thread waits to join, EINVAL. A detached thread is collected when it ends. - Stops by name: a join or detach of the main thread, on which the runtime runs the boot.

POSIX names (libScePosix). They return the error number itself: - pthread_create(thread, attr, entry, argument) is scePthreadCreate without a name. The executable's job threads (0x00466674, 0x004666df) pass a detached attribute with a stack size and a priority. - pthread_exit(value) is scePthreadExit (one call, 0x004667e3). - pthread_attr_setschedparam is scePthreadAttrSetschedparam. The job threads take their priorities from a table of 256, 650, 700, 750 and 767 (0x02fc5480), inside the range the SCE name accepts.

scePthreadAttrSetinheritsched(attr, inherit) chooses between PTHREAD_INHERIT_SCHED (4, libthr's default: a new thread starts at its creator's priority) and PTHREAD_EXPLICIT_SCHED (0: it starts at the attribute's priority), FreeBSD <pthread.h>'s numbers. libSceFios2's thread helper (+0x2eaa2) asks for explicit scheduling and then sets the priority. A variable without an attribute is EINVAL. Stops by name: another value (libthr's ENOTSUP, whose SCE value is not established, as for the policy), and explicit scheduling without a priority set (the attribute's default priority is not established).

scePthreadOnce(once, init) runs init once per once variable (libthr thr_once.c). The variable's first int is its state: 0 never done (the static initializer), 1 done, 2 in progress, 3 in progress with waiters. A caller that finds it in progress waits for the end; any other state is EINVAL. libc.elf calls it five times (+0xad02, +0x1b292, +0x54ecb and two tail calls) with a static variable and a routine. Nothing cancels a guest thread, so a routine always runs to its end.

scePthreadRename(thread, name) records a thread's name (OpenOrbis libkernel.h; libthr's pthread_set_name_np, to which shadPS4 binds it, facts only). The executable's job threads rename themselves with it (a tail call at 0x00466834). The runtime keeps the first 31 bytes, as for the name scePthreadCreate takes, names the host thread with the first 15 (the host's limit; debuggers and the host's thread list show it), and answers 0. Stops by name: a thread the runtime does not know or has collected, and a missing name.

The user service's start-up calls (libSceUserService, issue #36)

What the runtime does. The real-time clock (libSceRtc)

The runtime gives the host's local time, and keeps ticks as its own convention (runtime/syslib/rtc.c).

Sources. - Signatures: OpenOrbis Rtc.h gives sceRtcGetCurrentClockLocalTime(date and time *), sceRtcGetTick(const date and time *, uint64_t *) and sceRtcSetTick(date and time *, const uint64_t *). It names sceRtcGetTickResolution without a signature; the executable's one call (0x010b70ea) takes no argument and uses the int32_t answer as ticks per second, a negative one being a failure. - The date and time is six 16-bit fields (year, month, day, hour, minute, second), then a 32-bit microsecond at offset 12, 16 bytes in all. Rtc.h gives the microsecond 16 bits, which cannot hold 999999. The Vita homebrew SDK's SceDateTime, of the same library family, gives it 32 bits in a 16-byte structure, and the executable copies the whole structure as 16 bytes. - Ticks: the executable compares ticks, takes their differences and asks for the resolution. It holds no constant relating them to another epoch (neither the span from 0001 to 1970 in microseconds or seconds, nor its negation). About 60 sites ask for the local time; those reached pass it straight to sceRtcGetTick.

What the runtime does. - The local time is the host's, in the time zone of the person running the runtime, as the console gives the one its owner set. A leap second shows as :59. - A tick is the runtime's own convention, the same in every call: microseconds since 0001-01-01 00:00:00 (proleptic Gregorian), 1000000 per second. sceRtcSetTick reverses sceRtcGetTick exactly. - Stops by name: a date out of range (including February 30 and February 29 of a non-leap century), a tick past the year 9999, a missing argument, and every error value.

Day of the week: sceRtcGetDayOfWeek(year, month, day) (0x024ee2a9, its answer packed into 3 bits) answers 0 for Sunday to 6 for Saturday. The PS4Recomp project's libSceRtc numbers the days so, and notes that a real PS4's ticks count from year 1, as these do; both are used as facts only. (The PSP SDK documents 0 as Monday, for an older library.) A date out of range stops by name.

Scripted input (pbboot --input-script SPEC, tools/boot.py --no-record --input-script SPEC). Signal masks (_sigprocmask, issue #34)

_sigprocmask(how, set, old) is FreeBSD's sigprocmask(2): the calling thread's blocked signals. A FreeBSD sigset_t is four 32-bit words, with signal n at bit n - 1. how is SIG_BLOCK (1), SIG_UNBLOCK (2) or SIG_SETMASK (3), and is ignored when there is no new set. SIGKILL and SIGSTOP can never be blocked, and are dropped silently.

The bundled libc's setjmp (libc.elf+0x2fcb0) reads the mask with SIG_BLOCK and no new set, and its longjmp (libc.elf+0x2fd00) puts it back with SIG_SETMASK.

What the runtime does. No signal is delivered to the guest yet. So the runtime keeps each guest thread's mask, a new thread starting with its creator's, and does not apply it to the host thread.

What stops by name: an unknown how. Its error is reported through the guest's errno, which the runtime does not model.

sigprocmask and sigfillset (libc.elf imports both from libkernel). sigprocmask is the same call under its POSIX name (FreeBSD's libc sigprocmask is the system call itself); its thirteen calls include +0x53f84, which blocks everything with SIG_SETMASK and a set from sigfillset and keeps the old mask. sigfillset(set) puts every signal in the set, each of the four words all ones (FreeBSD libc's sigsetops.c, POSIX), and answers 0. A missing set stops by name: POSIX defines no error for it.

sceKernelClockGettime(id, tp) is the same call under its SCE name. It returns 0x80020000 plus the error number: EINVAL for another clock and EFAULT for a missing timespec, as FreeBSD answers them. The executable's call (0x0111a815) asks for clock 4, and treats anything but 0 as failure.

Process time (sceKernelGetProcessTime, issue #34)

uint64_t sceKernelGetProcessTime(void), as the OpenOrbis homebrew SDK's libkernel.h declares it, is the time since the process started.

Its unit is microseconds. The executable turns it into seconds by dividing by 1,000,000: - at 0x00e4fb6e, through the compiler's multiply by 0x431bde83 and shift by 50; - at 0x0252607e, through a division by the double 1000000.0.

It also seeds a random generator with it (0x00835dba).

What the runtime does. It measures from its own start, on the host's monotonic clock.

Audio job manager (libSceAjm, issue #37)

AJM decodes compressed audio in batches of jobs that the title builds in a buffer and hands over. The facts come from shadPS4's libSceAjm, checked against bbhost (a Bloodborne host, whose observations of the title's FMOD are noted) and PS4Recomp. The ATRAC9 configuration word's layout and tables are LibAtrac9's (MIT). The code is the runtime's own.

Contexts, codecs and instances. - Contexts: sceAjmInitialize(0, &context) and sceAjmFinalize(context). - Codecs: sceAjmModuleRegister(context, codec, 0) and sceAjmModuleUnregister, with 0 MP3, 1 ATRAC9 and 2 AAC. - Instances: sceAjmInstanceCreate(context, codec, flags, &instance) gives an id that is the slot index with the codec at bit 14. Its flags hold a revision (bits 0–2, not 0), the channels (3–6), the sample format (7–9, 0 for 16-bit) and gapless looping (bit 10). - The title's instances: it creates ATRAC9 instances with flags 0x409 to 0x441: revision 1, 1 to 8 channels, 16-bit, gapless looping (0x01118d9a).

Jobs and batches. - Building jobs: sceAjmBatchJobControlBufferRa and sceAjmBatchJobRunBufferRa write a job into the batch and return the next free position. - A job is a sequence of chunks, each with a 32-bit header: an identifier in bits 0–6 and a 20-bit payload. The chunks are the job itself (payload the instance), an optional return address, input and output buffers ({header, size, pointer}) and the flags. - Fixed sizes: a control job is 0x30 bytes (0x40 with a return address) and a run job 0x40 (0x50). The title's FMOD lays jobs out at those strides. - Starting and waiting: sceAjmBatchStartBuffer runs the batch (a size that is not a multiple of 8 is malformed, 0x80930011). sceAjmBatchWait waits with a timeout in ms; sceAjmBatchCancel and sceAjmBatchErrorDump round it out.

Job flags: - run: bit 11 get codec info, bit 12 multiple frames; - control: bit 13 reset, bit 14 initialize, bit 15 resample; - sideband: bit 45 gapless, bit 46 format, bit 47 stream.

A job's output control buffer starts with its result, then the stream result, format, gapless state, frame count and codec info, as its flags ask. The ATRAC9 codec info is {superframe bytes, frames per superframe, bytes left in the superframe, samples per frame}.

What the runtime does. - When jobs run: when the batch is started, on the calling thread (bbhost does the same for this title). A wait finds the batch finished and frees its id; a cancel of a batch that has run does nothing. - Control jobs are modelled: initialize with the 4-byte ATRAC9 configuration word, reset, and gapless. So is the codec info, derived from the configuration word: 0xFE, a sample rate index, a channel configuration, a 0 bit, the frame bytes minus one, and a superframe index, read most-significant bit first. - Errors: context 0x80930002, instance 0x80930003, batch 0x80930004, parameter 0x80930005, no batch id left 0x80930006, no instance left 0x80930007, already registered 0x80930009, not registered 0x8093000A, revision 0 0x8093000B.

Decoding. ATRAC9 is decoded with LibAtrac9 (MIT, vendored unmodified in third_party/libatrac9), behind a small decoder interface (runtime/ajm.h). The decode loop answers as shadPS4's does: - Before each frame: too little output room answers "not enough room" (0x10), and less input than the rest of the superframe "partial input" (0x8). - Each frame: it drops the gapless skip and stops at the gapless total. A superframe's padding is skipped, and when the gapless window ends mid-superframe the rest of it is decoded and dropped. - Looping and repeats: an instance with gapless looping starts the window again. A job repeats frames only with "multiple frames". - Errors: a decoder error is fatal, with its code as the internal result.

The tests use a stand-in decoder, because no ATRAC9 data may be in the repository, plus the real one on junk input.

Stops by name: codecs other than ATRAC9, sample formats other than 16-bit, resampling, format inputs and outputs, and the statistics instance.

Audio output (sceAudioOutInit, sceAudioOutOpen, sceAudioOutSetVolume, sceAudioOutOutput, issue #37)

The OpenOrbis homebrew SDK's AudioOut.h declares int32_t sceAudioOutInit(void) and int32_t sceAudioOutOpen(user, port type, index, length, sample rate, param). Its _types headers give: - port type 0 (main); - format 4 (float stereo); - the error codes 0x8026000E (already initialized) and 0x8026000F (not initialized).

What the executable does: - Its only init call (0x0111b665) accepts success or exactly 0x8026000E. - Its only open (0x0111b69d) passes user 0xff (the system user in the SDK's user types), the main port, index 0, 256 samples, 48000 Hz and a format. It keeps a non-negative result as the port handle. - The format is the executable's own evidence. Its output callback (0x0111b600) accepts 2 or 8 channels and passes 4 | (channels == 8). So 4 is float stereo (as in the SDK) and 5 is float with eight channels. The boot opens eight channels. - A second open (0x0111b6fc) passes port type 1 with the same settings, and does not check the result. The PS4 name of type 1 is not public; the sibling Vita SDK calls it BGM. - The movie player's sound gets a port of its own (0x02c225ae, 0x02c22842): 1024 samples at 48000 Hz. Its format comes from the movie's channel count: 0, 1 or 2 (16-bit mono, stereo, eight channels) for 48 kHz sound, and 3, 4 or 5 (float) otherwise. The SDK's _types/audio_out.h names 0, 1, 3 and 4; shadPS4's audioout.h adds 2 and 5 as the eight-channel forms. The 6-channel movies open format 2. With --audio host, 16-bit blocks are scaled to -1..1 for the host stream.

What the runtime does. It records each open port and hands out handles from 1. Sound output belongs to the output calls, which stop by name until they are implemented.

What stops by name: any open other than the observed ones (256 float samples in formats 4 and 5, or 1024 samples in formats 0 to 5, at 48000 Hz), and running out of handles.

int32_t sceAudioOutSetVolume(handle, flag, int32_t *volume), as the SDK declares it, comes next. The executable's only call (0x0111b6d6) passes its new port, flag 0xff and eight volumes of 32768, and treats nonzero as failure. Flag bit n selects channel n, whose volume is volume[n].

What the runtime does. It records the volumes.

What stops by name: - a handle it did not hand out; - a flag naming a channel the port does not have; - a missing array; - a volume outside 0–32768.

int32_t sceAudioOutOutput(handle, const void *samples), as the SDK declares it, hands a port sound. The executable's audio thread (0x0111b93c) hands its port one block at a time (length samples for every channel). It advances its ring buffer when the result is not negative, and loops with no wait of its own. So the call itself paces the thread: it returns once the port has room for the next block.

What the runtime does. It plays nothing yet. - Each port takes one block per length / rate seconds (256 samples at 48000 Hz: 5.33 ms). - A call waits until the block before it would have finished playing, then answers 0 (the caller only checks the sign). - A port that falls behind starts again from now.

What stops by name: a missing block, and a handle the runtime did not hand out.

int32_t sceAudioOutGetPortState(handle, void *state), as the SDK declares it, reports a port's state. Its _types/audio_out.h gives the layout (32 bytes): a 16-bit output, an 8-bit channel count, a volume and a 64-bit flag. The executable's only call (0x0111bb41) asks about its second port, and reads only output, testing it for 0.

What the runtime does. It plays nothing on the host, so no port is output anywhere. It answers output 0, and 0 in the fields whose encoding is not established. This must change when the runtime plays sound.

What stops by name: an unknown handle, and a missing state.

Sound on the host (pbboot --audio host, tools/boot.py --audio host). With this option, each port plays through SDL3 on the default playback device (runtime/audio_host.h, runtime/audio/audio_host_sdl.c). Without it, or in a build without SDL3, nothing is played and ports keep time on their own as before. Boots are silent by default.

  • Each block: each channel is scaled by its volume (32768 is 0 dB, the level the title sets; until it sets one the port plays at 0 dB, the runtime's choice) and queued on the port's stream.
  • Pacing: the call returns once no more than four blocks wait to be played, so the title's audio thread runs at the device's pace.
  • Channel order: the title's 8-channel float format (format 5) is passed in SDL's 7.1 order, as shadPS4's SDL backend does; the STD layouts, which are remapped, are not used by the title.
  • Port state: a port playing on the host reports output 1 (CONNECTED_PRIMARY, shadPS4's audioout.h).
  • Observed: with ATRAC9 decoding, a boot plays the game's own sound after about 17 seconds.

The movie player (libSceAvPlayer)

The title's files: /app0, sceKernelStat, opening and reading (issue #35)

The title reads its own data under /app0, the console's read-only mount of its package. The runtime serves /app0 from your own copy and never writes to it: - tools/boot.py --app0 DIR chooses the copy, defaulting to $BB_APP0, then $BB_DATA_ROOT/merged. - pbboot takes it as --app0. - A path under any other mount, and one with a .. component (which could leave the copy), stops by name.

sceKernelStat(path, struct stat *) is FreeBSD's stat(2) under its SCE name, which returns 0x80020000 plus the error number. The PS4's struct stat is FreeBSD 9's amd64 layout, 120 bytes (OpenOrbis' _types/kernel.h, OrbisKernelStat).

What the executable does. Its call at 0x02474519 asks whether /app0/dvdroot_ps4/sound/sprj_mixer.fev exists: - 0 means yes; - exactly 0x80020002 (ENOENT) means no; - anything else goes to its error path.

What the runtime does. It fills the structure from the host file: - type, size, block count and size, link count and times; - the permission bits without write (the mount is read-only); - device and inode numbers as the host's (they only identify the file); - the birth time as the modification time (the host's stat has none); - owner, group, flags and generation 0.

Errors. A missing file answers ENOENT, and a missing directory component ENOTDIR (the same numbers on FreeBSD and Linux). Any other host error stops by name.

POSIX stat and errno. eboot also imports POSIX stat from libScePosix. The runtime gives it the same lookup and answer, the POSIX way: 0, or -1 with the calling thread's errno set to ENOENT (2) or ENOTDIR (20). The executable's one call (0x00465431) reads the access and modification times and the size on 0, and treats any other answer as no file.

errno is libkernel's __error(), FreeBSD's int *__error(void) behind the errno macro. It is imported by eboot, libc and libSceFios2. Each guest thread runs on its own host thread, so a thread-local int is that thread's errno; it starts at 0, and success leaves it alone.

Truncating by name, and the POSIX mkdir, rmdir and rename

sceKernelTruncate(path, length) (imported by eboot and libSceFios2) is FreeBSD's truncate(2) under its SCE name: 0, or 0x80020000 plus the error number. The shape is OpenOrbis libkernel.h's; the executable's wrapper (0x024733a4) passes a 64-bit length and turns each 0x8002xxxx answer into an engine error through a table (0x02473530). eboot also imports mkdir, rmdir and rename from libScePosix: 0, or -1 with errno set. The executable's calls (0x00df0bf4, 0x00e03e68, 0x00e03ddb and others) ignore the answer or only compare it with 0. (sceKernelRename and sceKernelFtruncate are under "Opening and reading".)

What the runtime does: - Paths resolve as for opening: /data, the mounted save data, and /app0. - Errors are FreeBSD's numbers, never the host's: ENOENT, ENOTDIR, EEXIST, EISDIR, EINVAL and ENOTEMPTY (66 on FreeBSD, 39 on Linux). - rmdir of a mount's own root is EBUSY (the man page's "mount point for a mounted file system"). - rename across mounts is EXDEV, after the source and the target's folder are looked up, in FreeBSD's order (stable/9 vfs_syscalls.c, kern_renameat). A directory over a non-empty one is ENOTEMPTY. - truncate with a negative length is EINVAL before the lookup (kern_truncate; Linux checks it first too); a directory is EISDIR. Growing a file fills with zero bytes. - A new directory's mode is mode & 0777 less the host's umask. The PS4 process's umask is not established.

What stops by name: - no path; - any change under a read-only mount (/app0, save data mounted to read). FreeBSD answers EROFS, but only after lookups whose order the runtime does not model for each call, and the title's callers change only /data and its saves; - renaming a mount's root; - any other host error (EACCES, ENOSPC, EIO and the rest).

Opening and reading

sceKernelOpen, sceKernelRead, sceKernelPread, sceKernelLseek, sceKernelFstat and sceKernelClose are FreeBSD's open(2), read(2), pread(2), lseek(2), fstat(2) and close(2) under their SCE names. The OpenOrbis homebrew SDK's libkernel.h declares the shapes. Each returns a result, or 0x80020000 plus the error number. The executable opens its data with flags 0 (O_RDONLY) and mode 0555.

What the runtime does: - Opening. It opens the host file read-only. A request to write, create, truncate or append answers EROFS, as FreeBSD does on a read-only mount. The lookup comes first: a missing file without O_CREAT is ENOENT. Other flag bits stop by name. - Descriptors. A descriptor is the runtime's own number, from 3 up, standing for a host descriptor (the title only passes it back). One the runtime did not hand out is EBADF. - Seeking. A whence other than 0, 1 or 2 (SEEK_SET, SEEK_CUR, SEEK_END, the same on FreeBSD and Linux), and a seek before the start, are EINVAL.

Writing

sceKernelWrite(fd, buf, n) (imported by eboot and libSceFios2) and sceKernelPwrite(fd, buf, n, offset) (imported by libSceFios2) are FreeBSD's write(2) and pwrite(2) under their SCE names, with the shapes from the same libkernel.h. Each returns the number of bytes written, or 0x80020000 plus the error number. Writes reach files under the writable /data mount, which sceKernelOpen opens with the requested access mode.

What the runtime does: - Order of checks. FreeBSD's order (stable/9 sys_generic.c, sys_write, sys_pwrite and kern_pwritev): the size, then the descriptor, then the offset. - EBADF. write(2) answers it for a descriptor that is not open for writing: one the runtime did not hand out (0 to 2 included, as for reading), and one opened read-only, which is every /app0 file and a /data file opened with O_RDONLY. - EINVAL. A negative pwrite offset, as for pread (pwrite(2): "The offset value was negative"). - The position. A pwrite leaves the file position where it was. A write past the end leaves a hole that reads as zero bytes, as the host file system does. A zero count writes nothing and answers 0. - The count. The answer is the host's count, which can be short. Linux writes at most 0x7ffff000 bytes per call, so a request between that and INT_MAX comes back short where FreeBSD would write it all.

What stops by name: - More than INT_MAX bytes. FreeBSD answers EINVAL above IOSIZE_MAX. That is INT_MAX while the debug.iosize_max_clamp sysctl is set (its default in FreeBSD 9; current FreeBSD defaults to 0), and SSIZE_MAX otherwise. The FreeBSD 9.0 write(2) page says INT_MAX. The PS4's setting is not known. - No buffer for a non-zero count, as for reading. - A pwrite on a descriptor opened with O_APPEND. POSIX writes at the offset. FreeBSD's write(2) BUGS section says its pwrite appends instead, and Linux does the same. The PS4's answer is not established. - Any host write error (ENOSPC, EIO, EFBIG and the rest).

What would settle the stops: guest call sites that pass these cases, or results observed on a console.

The disc map (sceDiscMapIsRequestOnHDD, issue #35)

sceKernelQueryMemoryProtection(void *address, void **start, void **end, int32_t *protection), as the OpenOrbis homebrew SDK's libkernel.h declares it, gives the protection of the mapping that holds an address.

Graphics are rebuilt at the engine level (issue #39), so the GNM calls answer what the engine expects back; the GPU is not emulated.

The OpenOrbis homebrew SDK's GnmDriver.h only names this call. The executable's only call (0x02ad3fb4) takes a 64-bit address and maps 128 KiB of direct memory there, for the GPU's tessellation factors: sceKernelMapDirectMemory with that address as a hint, protection 0x33, alignment 0x10000.

What the runtime does. The PS4 answers a fixed address of its own. The runtime answers one it reserves for this, 0xfe00000000: below 2^40, and clear of the executable, modules and thread objects. It is the runtime's choice, not the PS4's value: the engine only maps it and hands it back to the GPU calls.

For this, sceKernelMapDirectMemory now takes an address hint as FreeBSD's mmap does without MAP_FIXED: the map goes there when the range is free. A hint in use (where the system then maps is not established) and one off the alignment stop by name.

Virtual memory queries (sceKernelVirtualQuery, issue #34)

sceKernelVirtualQuery(address, flags, info *, size), as the OpenOrbis homebrew SDK's libkernel.h and _types/kernel.h (OrbisKernelVirtualQueryInfo) declare it, describes the mapping that holds an address. The answer is a 0x48-byte structure:

Offset Field
0x00, 0x08 start and end
0x10 the direct memory offset
0x18 protection
0x1c memory type
0x20 flag bits: flexible 1, direct 2, stack 4, pooled 8, committed 0x10
0x24 a 32-byte name

What the executable does. Every call passes flags 0 and size 0x48, and reads the start, the offset or the direct bit: - 0x02d0328c works out an address's place in direct memory as offset + (address - start); - 0x02ad3f5e, 0x02ad4066 and 0x02ad423e release the direct memory at the offset.

What the runtime does. It answers from its record of direct and flexible mappings: start, offset, protection as asked for, memory type, flexible or direct, committed, and no name. No call reads the end, and whether it is inclusive is not established; the runtime writes the address just past the mapping.

What stops by name: - flags other than 0; - a size other than 0x48; - an address outside those mappings (other memory is not tracked yet); - a missing structure.

Unmapping, protecting and typing memory (sceKernelMunmap, sceKernelMprotect, sceKernelGetDirectMemoryType, issue #34)

The shapes are OpenOrbis libkernel.h's: sceKernelMunmap(address, length), sceKernelMprotect(address, length, protection) and sceKernelGetDirectMemoryType(start, &type, &range_start, &range_end).

What the executable does: - It frees a direct map with sceKernelMunmap and then sceKernelReleaseDirectMemory (0x024826fd, 0x0248270c), the order the release needs. - 0x02d03214 wraps sceKernelMprotect and answers whether the result was 0. - 0x02abae74 passes the pool offset sceKernelVirtualQuery gave for an address to sceKernelGetDirectMemoryType and only tests whether the type is 3 (write-combined garlic).

What the runtime does: - Munmap is FreeBSD's munmap(2). A zero length is EINVAL (FreeBSD's sys_munmap; shadPS4's sceKernelMunmap answers the same, facts only). It removes one whole mapping the runtime made: the host mapping goes, and a direct map no longer holds its range, which can then be released. A GPU-visible range can be mapped again at its GPU address. The address is not handed out again for other maps. - Mprotect is FreeBSD's mprotect(2): the mapping takes the new protection, the CPU bits on the host and the GPU bits recorded, as for a map. The queries answer the new protection. - GetDirectMemoryType answers the memory type of the allocated range that holds the pool offset, and that range's start and end (just past it, as for sceKernelVirtualQuery).

What stops by name: - part of a mapping, more than one, or memory the runtime did not map (other memory is not tracked yet); - an offset outside every allocated range (shadPS4 answers ENOENT; no public source settles it); - protection beyond CPU and GPU read and write; - a missing variable.

sceKernelReleaseFlexibleMemory stays unimplemented: shadPS4 gives the pages back and keeps the mapping, and no public source says whether the PS4 does that or unmaps.

GNM: binding vertex and pixel shaders (sceGnmSetVsShader, sceGnmSetPsShader, issue #39)

sceGnmSetVsShader and sceGnmUpdateVsShader take (command buffer, dwords, registers, modifier); sceGnmSetPsShader and sceGnmUpdatePsShader take (command buffer, dwords, registers). The argument order is shadPS4's libSceGnmDriver (gnmdriver.cpp). A boot shows the registers argument holding the shader's register block (7 words for a vertex shader, 12 for a pixel shader; see Paleblood's docs/RENDERER.md).

Detail Answer
The reserved space one PM4 NOP packet, as for the other command-buffer writers

The vertex shader's modifier replaces PGM_RSRC1's SGPR count (bits 6-9) and input VGPR count (bits 24-25): (PGM_RSRC1 & 0xfcfffc3f) OR the modifier, as shadPS4 applies it. The game's vertex shaders pass one (they call a fetch shader). A modifier with any other bit stops by name

GNM: compute queues (sceGnmMapComputeQueue, issue #39)

OpenOrbis' GnmDriver.h only names this call, so its shape comes from the engine's wrapper (0x01489a80, called from its compute queue setup at 0x0148c7b0).

What the engine does: - The wrapper passes the pipe and queue from the queue object, the ring buffer, its size in dwords, and the address of the GPU's read pointer. - A negative result is failure. Otherwise the wrapper keeps the result as the queue's id, and sets the read pointer to 0. - The setup then reports success only when that id is not 0.

What the runtime does. It does not run the GPU, so the ring is never read. It records each queue for the engine-level graphics layer, and answers ids from 1.

What stops by name: mapping the same pipe and queue twice, and a missing ring or read pointer.

Kernel event queues (sceKernelCreateEqueue, sceKernelWaitEqueue, sceKernelDeleteEqueue, issue #34)

The PS4 kernel is FreeBSD's, whose kqueue delivers struct kevent: ident (64-bit), filter (16-bit), flags (16-bit), fflags (32-bit), data (64-bit) and udata (a pointer), 32 bytes on amd64. The OpenOrbis homebrew SDK's libkernel.h declares create and delete; its _types/kernel.h lists the filters (display -13, graphics core -14, ...).

What the executable does. Right after asking video out for a flip, it waits with room for one event, a variable for how many came back, and no timeout (0x015e41b6, 0x02ad6f26). So the wait blocks until the flip is done.

What the runtime does: - The queue is a list of registrations, added and triggered by the runtime's own event sources (runtime/include/runtime/equeue.h; video out is the first). - A wait returns the triggered events, oldest first, and clears them, so each is reported once per trigger. - An event's flags and fflags are 0: what the PS4 sets there is not established, and no caller reads them.

What stops by name: - a timeout (no call passes one); - deleting a queue a thread is waiting on; - an event array or count that does not fit; - the error values.

Video out (libSceVideoOut, issue #38)

The OpenOrbis homebrew SDK's VideoOut.h declares the calls. Its _types/video.h gives: - the 40-byte buffer attribute: format, tiling mode, aspect, width, height, pitch in pixels; - the 64-byte flip status: flip count, two times, the flip argument, pending counts, current buffer; - flip rates (0: 60 Hz, 1: 30 Hz, 2: 20 Hz) and flip modes (1: vsync, 2: hsync).

What the executable does. It sets video out up twice, in the same order (0x015e488e and 0x02ad61d4): 1. open, with (0, 0, 0, no parameter); 2. flip rate 0; 3. an event queue with a flip event; 4. a buffer attribute (format 0x80000000; 1920 × 1080 in the first); 5. its buffers.

Each frame, it submits a flip with mode 2 and waits on the queue (0x015e419a, then 0x015e41b6). Its other loop (0x02ad6ee9) reads the flip status until the flip argument reaches the frame it submitted.

What the runtime does. It has no display yet. It keeps each port's buffers and status, and an hsync flip completes at once: - the current buffer and flip argument change, and the flip count grows; - the port's flip events are triggered.

The flip event's ident is 0, and its data the flip argument. The PS4's values are not established, and no caller reads them.

What stops by name: - a vsync flip, and other flip modes or rates; - a flip status before the first flip (its initial argument is not established); - other open arguments; - errors.

The buffer-attribute setter and buffer registration share the 40-byte rt_video_out_buffer_attribute layout. The setter copies all six input DWORDs without interpreting them and clears the 16 reserved bytes; unaligned output is supported. The public API is void. The independently examined native leaf also leaves the zero-extended pitch in RAX, which this implementation preserves for callers that observe it. A null output stops by the API name before any store.

Implementation rule

Implement the established contract and test the RT_SYSLIB entry through its library and symbol name. Keep target-specific values separate from host values. When an argument, ID, return value, or error case is unknown, fail loudly with the call name and leave the question open; never choose a value to make tools/boot.py advance.

Module TLS (__tls_get_addr)

Boot assigns TLS module IDs in mapped-object order, beginning at one, and prepares all nonempty templates before module entry. The executable reuses its static TLS block: the base is the thread pointer minus its rounded allocation size. Other blocks copy the relocated initialization bytes, zero-fill the rest and respect alignment. Lookup allocates nothing. Each context belongs to its host thread; unbinding and rebinding retain values, and destruction preserves borrowed storage. scePthreadCreate installs static executable TLS but no module context, so module lookups on those threads stop as __tls_get_addr.

Evidence and limits

The libkernel library SHA-256 is b3e13917da667d01a353ccf49025d6b1308a32cf86f3f351f96b3a13cd5c7c2f. Its __tls_get_addr export, NID vNe1w4diLCs, begins at ELF address 0x289c0. The body reads a two-word 64-bit module/offset index, consults TCB/DTV and linker state, masks a slot to 48 bits and adds the full offset without a bounds check. Invalid states can diagnose and execute INT 0x44. Generation updates, lazy allocation, alternate modes and linker helpers remain unsupported. Adjacent helpers at 0x2a9a0 and 0x2aca0 do not establish a general allocation-residue rule. The title libc template has virtual-address residue 8, while LibcInternal has zero; this implementation aligns the block base to the template's declared alignment.

Paleblood accepts full-width IDs and offsets through the template's logical size, including a one-past pointer. Unknown IDs, larger offsets and absent contexts stop by name. These bounds are runtime support limits, not native error behavior. There is no native DTV layout, lazy loading or unloading. The initialization model follows the TLS ABI and Oracle linker documentation. No other PS4 runtime implementation was used.

Validation

The loader rejects duplicate headers, initialized size beyond logical size, out-of-file bytes, inconsistent segment aliases, invalid alignment and templates outside the mapped image. Zero alignment becomes one; TBSS need not be readable. Boot checks allocation arithmetic and allocates aligned storage. test_module_tls checks the registry, initialization, owned 256- and 4096-byte alignment, zero-fill, stable writes, borrowed storage, separate threads, full-width requests and named stops. test_module_tls_boot.py runs synthetic AMD64 fixtures through boot, checking static/dynamic main-block aliasing, rounded sizes, module-ID relocations, relocated pointers, constructor persistence and rejected IDs. Loader tests cover malformed metadata.
