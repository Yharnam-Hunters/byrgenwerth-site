Evidence & Media Review

How to read a claim

Byrgenwerth explains how Bloodborne works from evidence gathered by Paleblood and its contributors. A test result, a trace, and a gameplay observation answer different questions, so pages label them separately.

Evidence label What it supports What it does not establish by itself
Verified original-game behavior A Paleblood replacement matched the original on the recorded and edge cases listed in its verification record, with independent review. Every possible input or every game state.
Direct static analysis A behavior or relationship visible in disassembly, callers, data references, or a readable replacement. That a code path ran in an observed play session.
Recorded original-game observation What happened in an original-game run or captured call, for the recorded conditions. Unobserved states or the reason behind an outcome.
Synthetic Paleblood test The tested Paleblood infrastructure or function behavior under the synthetic fixture. Original-game execution or a real production capture.
Paleblood-owned infrastructure A project-created loader, host interface, diagnostic, test, or tool and its demonstrated behavior. That the full game uses or reaches it.
External research A cited fact or interpretation from a named outside source. Independent confirmation by Paleblood.
Hypothesis / open question A plausible interpretation that guides further investigation. A confirmed function purpose or game rule.

When a claim combines evidence types, state which part each type supports. Link to the exact source revision, test record, or published source that supports it. Merging a pull request or closing an issue is not evidence that game execution advanced.

Screenshots, clips, and other media

The public documentation site may use an individual image or short clip when it materially helps explain a technical point, or supports criticism, research, or commentary. Each proposed asset needs its own provenance and rights review before it is copied into this private source or published. Attribution and educational intent are relevant context; neither alone grants permission.

The review must identify the source, creator and rights holder where known, intended use, amount shown, attribution terms, permission or license (or a reasoned, asset-specific legal basis for the proposed use), privacy and security concerns, accessibility text, resizing or redaction, and maintainer approval. Use only the smallest portion and resolution that explains the point. Do not publish extracted assets, proprietary captures, bulk game text, secrets, or material whose source cannot be established. Do not republish retired image collections or describe another project's screenshots as Paleblood output.

The Paleblood code repository has its own stricter rule: game screenshots, clips, extracted assets, game files, and decompiler output do not belong in its source, issues, pull requests, or Discussions. A media review for this site does not authorize placing media in the code repository.

Current media record

The site menu shows the 256×256 Bloodborne menu artwork credited to r_dsgnd on SteamGridDB. It appears once per page as a small image at the top of the sidebar, above the Home link, with descriptive alt text, visible contributor/source attribution, and a link to the source entry. The private asset record explains the supplied file's provenance and pixel match to the former wiki icon, intended display size, copyright rationale, and unresolved rights status. No license for redistribution of the underlying game artwork was found; contributor credit and the educational/research context are not treated as permission or as a guarantee of an exception. This specific use is presented for maintainer review. The retired gallery remains absent. An original SVG diagram elsewhere in the encyclopedia is Paleblood-owned and contains no game imagery.

Maintainers keep the detailed per-asset record privately; those records are not included in the generated website.
