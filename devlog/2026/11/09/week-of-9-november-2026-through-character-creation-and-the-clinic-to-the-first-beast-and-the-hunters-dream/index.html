2026-11-09

Week of 9 November 2026: through character creation and the clinic to the first beast and the Hunter's Dream

In local runs with scripted input the game now gets past its title: save data, the main menu, the Brightness and Controls screens, the opening cinematic in 3D and character creation, then into Iosefka's Clinic, which draws through the game's own post-processing and at the right brightness; by 14 November the clinic's first encounter runs with no stop, from the walk up to the beast and its first attack to "YOU DIED" and waking in the Hunter's Dream, and the clinic went from about 6 to about 11 fps. The runtime checklist is done (all eight issues closed), evill33t's Metal executor grows on macOS, function families replace thousands of tiny functions at once (a large share by count, a very small one by bytes), and every function is tagged with its likely source file. Over 18,000 family members and 264 hand-written functions became verified, the family members by byte-exact matching and the others on inputs recorded in the game, including the clinic beast's sight and perception; its hearing is decompiled and edge-verified. Work by @EzequielRindello, @BluePinetree, @evill33t, @FFwLo, @Jeffiest and a lead from @sweetbbak.

Runtime and boot progress

So far this week: past the title, through character creation, into Iosefka's Clinic (local runs). Advances game execution in the maintainer's local runs; the boots recorded on merged main (#536, #571, #656; display off, no input) still wait at the title, as expected without input.

  • With scripted input, the maintainer's local runs take "Play Offline", create the save data, show the main menu and, after New Game, the first-run Brightness and Controls screens; scripted on, the game's opening cinematic draws in 3D, lit, and plays to its end, and the game reaches character creation (the contract screen). On 11 November its 3D preview of the hunter draws: first into the G-buffer (#593), then lit (#599, #600, #606), then in the right colours (#607, with #609 for the face, applied from review and merged the same evening), at about 9 frames a second. Frames: Milestones.
  • The runtime checklist is done. Every system import the boot reaches is answered; the boot record of 10 November (#536) shows 683 of the 686 bound (219 by the game's own modules, 464 by the runtime). The last three, sceKernelMkdir, sceKernelRmdir and sceKernelUnlink, are @EzequielRindello's in #455, merged on 11 November as #555. The C library's affinity query followed the same day (#561): it answers the mask set on the attribute, otherwise all ones, as the maintainer ruled on 10 November, building on @evill33t's groundwork in #239; the console's own mask is still not measured. All eight runtime issues, #34 (184 of 184 calls) to #41, are closed.
  • Contributors: @EzequielRindello's sceKernelWrite and sceKernelPwrite (#444), the save code's first writes after "Creating save data", and _exit (#454); @BluePinetree's check of a module hook's first bytes before patching, so another libc.elf build is refused by name (#456).
  • A first batch of runtime calls merged on 10 November, each with its own tests: renaming, truncating and folders #458; deleting a save and the disc map #459; thread join, detach, explicit scheduling and once #460; timed mutex and reader-writer locks #464; unmapping, protecting and typing memory #467; signal masks and thread names #469; time zones, RFC 2822 dates and the network tick, and no system events #466; the C library's calendar and formatted output for the file library #468; the pad's motion settings and an unplugged mouse #462; offline PSN authorization and the IP address query #461; IPv4 address to text #465.
  • A second batch answered the rest: directories and flushing #498; the four common dialogs, closed at once #500; the on-screen keyboard, cancelled, and the browser, not opened #502; no microphone, no voice chat, and GNM queries and debug calls #506; the remaining PSN services, signed out #507; sockets, resolver and HTTP requests with no connection #509; the C library's imports from the kernel #513, #521; the maintainer's rulings for page size, process id, the stack canary, exception landing pads, module information and reserved address space #528; the last graphics calls, with graphics events raised from the GPU's completion step #532; a movie's sound port closing #490; file paths kept off small thread stacks, which crashed one boot in five #512.
  • Past the contract (11 and 12 November). The contract needs a name, and the runtime's keyboard was always cancelled; with --keyboard-text it answers as if the name was typed (#619), so a scripted boot names the hunter and finalises the contract. The loading screen after it needed the GPU's constant engine (#622) and writes in order with the work (#624, #627). The game autosaves there, and tools/boot.py --savedata-from starts a boot from a copy of that save (#641): the title offers Continue and the boot goes straight into the load of Iosefka's Clinic, which needed indirect dispatches (#649) and DMA_DATA copies through the global data share (#653) and stops next at tessellation (#655). No frame of the clinic itself is drawn yet. Frames: Milestones.
  • Into Iosefka's Clinic (12 and 13 November). The first clinic frame (12 November) was the HUD over a flat grey world, drawn with the GPU work fed one submission at a time as a local debugging setting: run normally, the renderer fell so far behind that the game's GPU memory rings ran out and the GPU hung. Submissions now wait four buffers ahead (#743) and out-of-range shader memory accesses stop by name (#731). The grey was the missing post-processing chain (YEBIS), whose indexed draws were never observed (#761); with them and its descriptor and memory fixes (#765, #771) the clinic went through the game's own post chain, about eight times too bright. The deferred lights were the cause: each is drawn once per 128x128 screen tile with the tile as the viewport scissor, which the renderer did not apply; with it (#807) the clinic matches a reference capture's brightness (13 November; both merged that day). One pipeline cache (#773) first took a frame from about 41 to about 6 seconds; with a compute state per GPU queue (#820) and resubmitted buffers checked against memory (#831) two compute stops that came at random times are gone, and the new frame log (#830) measured the clinic at about 6.3 fps on average in a local run (1% low about 4.5), against the game's 30. Clip control (#802), image loads outside the image (#804) and waits after submission (#806) merged too. Frames on Milestones.
  • Boot record of 12 November (#656, merged main, display off, 30 seconds): first flip, 686 of 686 imports bound, 248 called, nothing stops it: the same as #571, as expected without input. The Contract screen on the same tree, measured locally with scripted input: 29.4 frames a second.
  • Audio output with no block: the movie player's sound thread can pass none when it has nothing to give, which stopped a slower run during the opening movie; the call now waits for room and hands nothing over (#481).
