2026-11-09

Week of 9 November 2026: past the title to character creation

In local runs with scripted input the game now gets past its title: save data, the main menu, the Brightness and Controls screens, the opening cinematic in 3D, and character creation; the logos and title run at 30 fps. The runtime checklist is done (all eight issues closed), evill33t's Metal executor grows on macOS, function families replace thousands of tiny functions at once (a large share by count, a very small one by bytes), and every function is tagged with its likely source file. Work by @EzequielRindello, @BluePinetree, @evill33t and a lead from @sweetbbak; no new function was verified. This post grows through the week.

Runtime and boot progress

So far this week: past the title, to character creation (local runs). Advances game execution in the maintainer's local runs; the boot recorded on merged main (#536, display off, no input) still waits at the title, as expected without input.

  • With scripted input, the maintainer's local runs take "Play Offline", create the save data, show the main menu and, after New Game, the first-run Brightness and Controls screens; scripted on, the game's opening cinematic draws in 3D, lit, and plays to its end, and the game reaches character creation (the contract screen). Frames: Milestones.
  • The runtime checklist is done. Every system import the boot reaches is answered; the boot record of 10 November (#536) shows 683 of the 686 bound (219 by the game's own modules, 464 by the runtime). The last three, sceKernelMkdir, sceKernelRmdir and sceKernelUnlink, are @EzequielRindello's in #455, merged on 11 November as #555. The C library's affinity query followed the same day (#561): it answers the mask set on the attribute, otherwise all ones, as the maintainer ruled on 10 November, building on @evill33t's groundwork in #239; the console's own mask is still not measured. All eight runtime issues, #34 (184 of 184 calls) to #41, are closed.
  • Contributors: @EzequielRindello's sceKernelWrite and sceKernelPwrite (#444), the save code's first writes after "Creating save data", and _exit (#454); @BluePinetree's check of a module hook's first bytes before patching, so another libc.elf build is refused by name (#456).
  • A first batch of runtime calls merged on 10 November, each with its own tests: renaming, truncating and folders #458; deleting a save and the disc map #459; thread join, detach, explicit scheduling and once #460; timed mutex and reader-writer locks #464; unmapping, protecting and typing memory #467; signal masks and thread names #469; time zones, RFC 2822 dates and the network tick, and no system events #466; the C library's calendar and formatted output for the file library #468; the pad's motion settings and an unplugged mouse #462; offline PSN authorization and the IP address query #461; IPv4 address to text #465.
  • A second batch answered the rest: directories and flushing #498; the four common dialogs, closed at once #500; the on-screen keyboard, cancelled, and the browser, not opened #502; no microphone, no voice chat, and GNM queries and debug calls #506; the remaining PSN services, signed out #507; sockets, resolver and HTTP requests with no connection #509; the C library's imports from the kernel #513, #521; the maintainer's rulings for page size, process id, the stack canary, exception landing pads, module information and reserved address space #528; the last graphics calls, with graphics events raised from the GPU's completion step #532; a movie's sound port closing #490; file paths kept off small thread stacks, which crashed one boot in five #512.
  • Audio output with no block: the movie player's sound thread can pass none when it has nothing to give, which stopped a slower run during the opening movie; the call now waits for room and hands nothing over (#481).

Renderer: what the menus, the cinematic and character creation need. Advances game execution in local runs.

  • 8- and 16-bit buffer formats, and stops that name the shader (#457): with them the main menu draws.
  • Depth and stencil tests that read the buffer, stencil steps and a depth target larger than the colour target (#471): choosing New Game needed all three; the boot then reaches the Brightness screen.
  • Image descriptors loaded behind a branch (#474), two-channel 8-bit images (#476) and samplers with anisotropy fields but plain filters (#477): the next scene after Controls, the opening cinematic, draws.
  • Speed: one GPU batch per submitted command buffer (#463, no measurable change by itself), then the render targets' tiling copies moved to the GPU (#472): the logos and title run at the game's 30 fps cap in local runs, up from about 14, with the JAPAN Studio frame still pixel-identical.
  • Submissions run beside the game, in order (#488): a submit returns at once and the renderer's own thread runs the work, with every "work done" value, wait and flip after the work before it. Compute queues' buffers are taken and dropped (#470).
  • For the rest of the cinematic and character creation: depth-only passes #519, depth target slices #522, mip chains and mip-mapped images sampled at the right level #516, #523, #526, stencil replace #524, several render targets in one draw #533, the front-face input #537, targets cleared by a compute shader #539, more image and float target formats #534, #492, #503, #525, #530, more instructions #495, #501, buffer accesses checked against their descriptors #494, #505, #508, #540, and 70 command buffers in one submit #504; then descriptors from wider loads, late user-data writes and literal offsets #547, #553, #559, unbound buffers reading zeros #556, output multipliers and clamps on float results #558, and up to sixteen images and samplers a shader, which character creation's preview needs #564, with room for its few hundred textures #563 and fast-clear eliminate passes skipped where no tile was fast-cleared #565.
  • macOS, by @evill33t: sound and video pacing on portable monotonic deadlines #538 and file times read macOS's own fields #541; an offscreen Metal draw executor behind the renderer's common interface #518, which then gained buffer-only compute, vertex fetch programs and render targets kept in step with the game's memory #562 (from #542 to #544). The device tests ran on the author's Macs and CI compiles them; infrastructure for macOS: the game does not run there yet.

Decompilation and verified functions

Decompilation. Infrastructure for the decompilation; no new function reached verified status.

  • Function families (#515, #527, #529, #531): tiny functions the compiler emitted thousands of times (empty methods, returns of 0 or a constant, field getters and setters, argument returns, a float zero) share one replacement per family, proved on every member with mutants. 19 families, 18,019 functions: 11.42% of the executable's functions but only 0.15% of its bytes. They move the count, not the code; Function families explains them and shows both numbers.

Tooling and automation

Tooling. Infrastructure only.

  • tools/source_files.py tags every function of the executable with its likely source file and library (#480), from the lead in issue #453 by @sweetbbak: the assertion messages keep each file's source path.
