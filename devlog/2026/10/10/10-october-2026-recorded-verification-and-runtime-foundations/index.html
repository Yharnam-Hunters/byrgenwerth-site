2026-10-10

10 October 2026: recorded verification and runtime foundations

This day improved capture reliability, verified one function from existing recorded calls, and added four deterministic network byte-order imports. The tooling work did not itself advance game execution.

Runtime and boot progress

Paleblood PR #50, merged at 816ea96, added sceNetHtonl, sceNetHtons, sceNetNtohl, and sceNetNtohs. These implement fixed-width host/network byte-order conversions; socket, resolver, epoll, and online behavior remain uncovered. The saved boot result still stopped at scePthreadAttrGetaffinity (238/686 system imports provided), within contributor-owned issue #34. No boot run was made for this change.

Paleblood PR #55 adds Paleblood's own version of the callback that redirects a game function to its replacement. A synthetic test confirms the redirect works. The full game run still uses the old runtime, which doesn't call this yet.

Decompilation and verified functions

Paleblood PR #48 promoted frame_timing_pace_frame (0x02434770) using its existing evidence: 585/585 recorded calls and 26/26 edge cases. Its approved independent review remained in place. PR #49 refreshed generated public documentation from the merged verification result; it added no runtime behavior or new cases. The verified function count reached 21.

Tooling and automation

Paleblood PR #46 made capture output stable, recorded function/run provenance, refused unsafe paths and existing case files, and kept older schema-1 cases replayable. PR #47 added an isolated typed adapter proof with explicit signature and memory descriptors. Synthetic fixtures passed capture, serialization, replay, and verification; unsupported signatures and missing descriptors failed closed. Production replacements still do not call this adapter, so these tests produced no real game captures.

Paleblood PR #53 lets the runtime issue counts see implemented system calls without waiting for a boot run. That corrected issue #41: its network group now shows the four byte-order helpers from PR #50, 4/175 implemented.

Paleblood PR #54 adds a test that checks how Paleblood talks to the old runtime: version checks, handing over the game image, registering redirects and passing errors back. It guards against regressions; nothing new runs.

PR #55 also made the repository's Git hook tests more robust: they respect the configured temporary directory and stop cleanly if their test copy can't be made. The tests confirm that the hooks refuse game code and block a push when a required check fails.

Documentation and website changes

The frame-timing page and generated progress data were refreshed from merged Paleblood revision 816ea96. The public site was published at 21e1d26. The runtime notes keep the production observer and capture integration explicitly unfinished. Public source documents the synthetic limits alongside the results.

All 30 public wiki pages were reviewed against the current Paleblood source, and the Runtime, Architecture and CI Setup pages were updated; the Runtime page now lists the four network byte-order helpers. Automatic syncing from Paleblood stays off until it can run with safe, limited credentials.

The first Workshop article explains the verified per-frame character points update (0x01cbdb20): how it keeps fractional amounts between frames, its limits, and the evidence behind it, with a diagram. Calling it "stamina" is still a guess, and the article says so.

A redesign put the wiki's pages into seven themed, collapsible menu groups that remember which ones you opened and work as a drawer on phones. The homepage got the hunter artwork chosen by the maintainer (SteamGridDB, by r_dsgnd) in place of a product image.

The redesign went live at public site commit 975ec0c. Every page loaded, the search index was up to date, and the phone menu opened, closed and moved focus correctly.

The sidebar menu was repaired and the artwork moved into it, above Home, with its credit beneath. Section headings line up and no longer wrap, submenus sit along a guide line, only one section opens at a time, and short windows scroll instead of squeezing the menu. The homepage now opens with Master Willem's words.

The repaired menu went live at public site commit 6b16b45, with the artwork in the sidebar and no longer on the homepage.

Tests and validation

The capture changes passed GCC and Clang builds and all 11 CTest suites. The verification promotion used the 585 recorded calls plus 26 edge cases. The four network helpers passed registry tests with known byte patterns, zero, maximum-width values, and round trips; both compiler builds and all 11 CTest suites passed. Clean-room, policy, hook, and session audits also passed.

Blockers and next steps

No production capture integration or game execution advanced. 0x02713870 still has no matching recorded inputs and remains blocked. The earliest saved boot blocker remains the issue #34 affinity import; synthetic capture tests are not substitutes for matching recorded cases or production ABI evidence.
