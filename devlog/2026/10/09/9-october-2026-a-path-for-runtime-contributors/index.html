9 October 2026: a path for runtime contributors

Runtime-only contributors can implement a documented syscall without access to a game dump or recorded captures. This day's work prepared the issue #34 contribution route and clarified what the current boot evidence does and does not establish.

Runtime and boot progress

The runtime still stopped at its first unresolved system call. The maintainer's boot check runs locally after a runtime pull request merges; a contributor does not need proprietary files or captures to implement and test a runtime-only change.

Decompilation and verified functions

No function replacement or verification status changed in this milestone. The frame limiter's clock calls pass a null timezone to gettimeofday; a separate sceKernelClockGettime call uses clock ID 4, but the IDs passed to the imported clock_gettime are still unknown. Those gaps remain open instead of being filled with assumed return values.

Tooling and automation

The issue #34 workflow uses a claim-and-branch process, small related changes, and a concise evidence report. Paleblood PR #44, merged at ef1989ec3388c26cddd20b13742ba93d09cc147e, prepared the contributor checks. Runtime-only pull requests use the compiler matrix, system-library tests, and policy checks. Decompilation and mixed changes retain the full session report and verification gates. Shared Git hooks dispatch through the active worktree, so linked worktrees use their own installed checks.

Daily posting now updates the existing local-date entry through stable milestone keys, ordered sections, and concurrent-safe atomic writes. The gated publisher also keeps the pinned Paleblood source revision separate from the public-site remote. Seven deterministic tests pass, including concurrent updates and repeat MkDocs output. These are documentation and workflow improvements; game execution did not advance.

Paleblood PR #51, merged at fe3661f, keeps boot outcome, phase, unresolved-import return site, and guest fault location in history, including when only the failure site changes. GCC and Clang builds and CTest passed 11/11 each; 93 Python tests passed. This improves diagnostics only; no game run or boot advancement occurred.

Documentation and website changes

The syscall notes distinguish public contracts for getpagesize, getpid, clock_gettime, and gettimeofday from target-specific behavior not yet established. The loading map records the bundled Fios module while leaving archive access, PlayGo flow, and target-specific error paths as open questions. Progress was synchronized from merged Paleblood sources.

Tests and validation

The issue #34 workflow added no replacement and no verification result. Runtime-only CI checks run without game data; pull-request CI validates the changed code and policy before the local post-merge boot check. The shared hook changes were exercised in linked worktrees.

Blockers and next steps

The first unresolved import and the target-specific behavior listed above still need evidence. The next runtime change should implement one documented call or a tightly related group, keep unknown behavior explicit, and include deterministic tests and its source basis.

The current Paleblood source has nine edge-verified functions, but none has matching recorded calls in the available capture library; the read-only promotion dry run produced no candidate. Issue #34 still has a contributor claim and remains the earliest boot blocker. Issues #35–#40 are unclaimed, but their current issue scopes list imports without enough target-specific contracts for a safe implementation. The existing 0x0183ac60 worktree was left untouched, and 0x02713870 still has no matching recorded inputs. No runtime behavior or game execution advanced.
